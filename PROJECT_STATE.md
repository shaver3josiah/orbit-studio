## Decisions log

- **Why cloud training**: the laptop's integrated graphics can render a finished splat smoothly through Spark, but it has neither the memory bandwidth nor the raw throughput to train one. Rather than requiring new hardware, training rides a free Google Colab T4 GPU, and everything else, capture, review, and flying through the result, stays on the laptop. Full reasoning is in the README's "Why this design" section.
- **Chosen stack and versions**: Spark 2.1.0 for splat rendering, three.js 0.180.0 underneath it, pycolmap tracking the COLMAP 4.1.0 era for pose recovery, gsplat tracked against its `main` branch for training, Brush 0.3.0 kept as an optional alternate trainer/viewer rather than a dependency.

## Orbit Tour — the Kuula replacement (added 2026-07-23)

- **What it is**: a second app in this repo at `tour/index.html`, served by the same `server.py` at `/tour`. Self-hosted 360 photo virtual tours: multi-scene, hotspots, embeds, standalone export. Replaces a kuula.co Pro subscription. Full docs: `docs/TOUR.md`.
- **Engine choice (research-backed, 2026-activity gate)**: Photo Sphere Viewer 5.14.3 + three.js 0.184.0, both vendored under `tour/vendor/` and pinned. Marzipano (archived Apr 2026) and Panolens (archived 2023) were disqualified for inactivity; Pannellum is 2026-active but has no VR/gyro/little-planet/gallery plugins, so it would have meant writing most of Kuula's feature set by hand. No open-source Kuula-clone editor was worth adopting (the one candidate is built on dead Marzipano).
- **Version rules that matter**: all `@photo-sphere-viewer/*` packages are exact-peer-lockstepped, and core 5.14.3 requires three `^0.184.0` which for a 0.x version means 0.184.x ONLY. `three.module.js` is a split bundle that relatively imports `three.core.js` — both must be vendored or the viewer dies on load. Never add `little-planet-adapter` (stale at 5.7.4); core's `fisheye` option is the supported path. See `tour/vendor/VERSIONS.md`.
- **PSV v5 ships ESM only** (no UMD), so the app loads it through an `<script type="importmap">`. That is also why the static export rewrites `/tour/vendor/` to `./vendor/` and not `vendor/` — bare specifiers are invalid as import-map addresses.
- **Storage**: `tours/<tour-id>/tour.json` + `files/` (gitignored, it is user content). Angles are stored in DEGREES in tour.json and converted to radians at the PSV boundary. Media filenames are server-generated hex tokens; the client never controls a filename on disk.
- **Prune grace window**: `prune_tour_files` deletes unreferenced media on save, but skips anything younger than `PRUNE_GRACE_SECONDS` (300). Without that window a debounced autosave firing between an upload and the save that references it silently destroyed the just-uploaded pano — confirmed live, then fixed and covered from both sides in the smoke test.
- **CORS**: the API now echoes only localhost-family origins instead of `*`, because the tours API has DELETE routes. Non-browser clients (the phone app, curl) send no Origin and are unaffected.
- **Tests**: `python tests/tour_smoke_test.py` (30 checks). `python tests/seed_demo_tour.py` generates a 3-scene demo tour with hotspots for eyeballing the viewer without a camera.
- **Build method**: each step was gated by an impeccable-agent report card requiring 93%+ before moving on — foundation 93%, viewer 94%, editor 93%, share/export 96%, and a final whole-product audit at 93% with no blockers. Defects the gates caught and that are now fixed: a data-loss race where autosave pruned a just-uploaded panorama; an invalid import-map path that would have broken every exported tour; a shared delete-arm variable that let one scene row arm while another stayed falsely armed; a settings object captured by reference that undo would have detached; undo restoring a scene whose media a save had already pruned; and custom icons silently dropped on link hotspots.
- **Known gaps vs Kuula Pro** (deliberate, documented): no view analytics, no password-gated tours (a read-only token would be theater while the same port offers unauthenticated edit/delete — the real answer is auth at a reverse proxy), stereo VR is cardboard-style split view rather than a true WebXR session, and no tiled loading for very large panoramas.

## Coordinate convention rule

Every 3D asset handoff states its up axis explicitly. Pipeline artifacts (gsplat and COLMAP output) are Y-down and the viewer applies the 180 degree X flip. Generated and web-native assets (demo.splat, user-dropped files) are Y-up and are never flipped. A handoff that does not state its up axis is not ready.
