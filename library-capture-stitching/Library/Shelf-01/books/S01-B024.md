# A Field Overlap Estimator: Comparing Consecutive Frames

You are standing in a room with a phone, shooting overlapping stills, and you have no way to know until you get home and run COLMAP whether you actually got enough overlap. "Overlap as the Currency of Structure-from-Motion" makes the case for why that number matters; this book is the tool that turns the question from a guess into a printed percentage while you are still standing in the room.

The idea is deliberately cheap. A full COLMAP feature-matching pass (SIFT detection, descriptor matching, geometric verification) is the ground truth for whether two images share enough structure to register together, but it is slow and meant to run once, offline, on the whole set. You do not want to wait on that between every few shots. What you want is a fast, rough, "close enough" estimate you can compute on a laptop or even on-device, applied only to consecutive frames in your capture sequence, that flags when a pair looks thin before you have moved on and lost the chance to fill the gap.

## Why "consecutive frames" and not the whole set

COLMAP's own sequential matcher makes the same simplifying bet: for ordered, video-like captures it only matches each image against a nearby window (`overlap`, defaulting to 10 images on either side) rather than every image against every other image, because in an ordered walk the images that matter for connectivity are the neighbors, not the far end of the room (COLMAP 3.6 Documentation — Tutorial; COLMAP sequential matcher overlap parameter and vocabulary-tree loop detection notes). Our estimator narrows that further, to the single next frame, because during capture the question you actually need answered in real time is "did I move too far since the last shot," not "how does this image relate to the whole building." Loop closure and cross-room matching are a different problem, covered by "Live Coverage Tracking: Am I Done With This Room?" This tool is the frame-to-frame tripwire, not the room-level map.

## The approach: ORB keypoints, a ratio test, and a cheap area proxy

We use OpenCV's ORB detector because it is fast, license-free, and built into `opencv-python` with no extra model download. This is a deliberate downgrade from COLMAP's own default of SIFT. The notes are clear that SIFT (and hand-crafted keypoint detectors generally) degrade badly on weak-texture, repetitive, or low-light surfaces, and that COLMAP itself recommends switching to a learned detector like ALIKED when overlap is already limited (COLMAP 3.6 Documentation — Frequently Asked Questions; SfM feature matching failure on texture-poor and repetitive surfaces study). ORB inherits the same weakness on blank walls, so this estimator is not a substitute for COLMAP's real matcher on a texture-poor room, only a fast field proxy for texture-normal ones. Say so out loud to whoever is relying on the number: a "good" reading on a blank hallway wall is not trustworthy the way it is on a bookshelf or a cluttered kitchen.

The pipeline per pair is: detect ORB keypoints and descriptors in both frames, match descriptors with a brute-force Hamming matcher, apply Lowe's ratio test to keep only matches where the best candidate is clearly better than the second-best, then estimate a homography from the surviving matches with RANSAC. The homography inlier count, not the raw match count, is what we treat as the signal, because RANSAC throws out matches that are geometrically inconsistent (moving people, reflections, repeated patterns), leaving the correspondences that actually describe camera motion between the two frames.

```python
"""overlap_estimate.py — frame-to-frame overlap proxy using ORB + RANSAC.

Not a substitute for COLMAP's SIFT/ALIKED matching + verification pipeline.
This estimates a fast, local signal for two adjacent frames only.
"""
from __future__ import annotations

import sys
from dataclasses import dataclass
from pathlib import Path

import cv2
import numpy as np

ORB_FEATURES = 4000
RATIO_TEST_THRESHOLD = 0.75
RANSAC_REPROJ_THRESHOLD = 5.0
MIN_MATCHES_FOR_HOMOGRAPHY = 8


@dataclass
class OverlapResult:
    path_a: Path
    path_b: Path
    keypoints_a: int
    keypoints_b: int
    raw_matches: int
    inlier_matches: int
    overlap_estimate: float


def load_gray(path: Path) -> np.ndarray:
    image = cv2.imread(str(path), cv2.IMREAD_GRAYSCALE)
    if image is None:
        raise FileNotFoundError(f"could not read image: {path}")
    return image


def estimate_overlap(path_a: Path, path_b: Path) -> OverlapResult:
    img_a = load_gray(path_a)
    img_b = load_gray(path_b)

    orb = cv2.ORB_create(nfeatures=ORB_FEATURES)
    kp_a, des_a = orb.detectAndCompute(img_a, None)
    kp_b, des_b = orb.detectAndCompute(img_b, None)

    if des_a is None or des_b is None or len(kp_a) < 2 or len(kp_b) < 2:
        return OverlapResult(path_a, path_b, len(kp_a or []), len(kp_b or []), 0, 0, 0.0)

    matcher = cv2.BFMatcher(cv2.NORM_HAMMING)
    knn_matches = matcher.knnMatch(des_a, des_b, k=2)

    good = [
        m for m, n in knn_matches
        if m.distance < RATIO_TEST_THRESHOLD * n.distance
    ]

    if len(good) < MIN_MATCHES_FOR_HOMOGRAPHY:
        return OverlapResult(
            path_a, path_b, len(kp_a), len(kp_b), len(good), 0, 0.0
        )

    src_pts = np.float32([kp_a[m.queryIdx].pt for m in good]).reshape(-1, 1, 2)
    dst_pts = np.float32([kp_b[m.trainIdx].pt for m in good]).reshape(-1, 1, 2)

    _, mask = cv2.findHomography(
        src_pts, dst_pts, cv2.RANSAC, RANSAC_REPROJ_THRESHOLD
    )
    inliers = int(mask.sum()) if mask is not None else 0

    denominator = min(len(kp_a), len(kp_b))
    overlap_estimate = inliers / denominator if denominator else 0.0

    return OverlapResult(
        path_a, path_b, len(kp_a), len(kp_b), len(good), inliers, overlap_estimate
    )


def scan_sequence(image_paths: list[Path]) -> list[OverlapResult]:
    return [
        estimate_overlap(image_paths[i], image_paths[i + 1])
        for i in range(len(image_paths) - 1)
    ]


def main(argv: list[str]) -> int:
    if len(argv) < 3:
        print("usage: overlap_estimate.py <dir_of_jpgs> <low_overlap_threshold>")
        return 1

    image_dir = Path(argv[1])
    threshold = float(argv[2])
    images = sorted(image_dir.glob("*.jpg"))

    if len(images) < 2:
        print("need at least 2 images to compare consecutive frames")
        return 1

    results = scan_sequence(images)
    for r in results:
        flag = "LOW" if r.overlap_estimate < threshold else "ok"
        print(
            f"{r.path_a.name} -> {r.path_b.name}: "
            f"inliers={r.inlier_matches}/{min(r.keypoints_a, r.keypoints_b)} "
            f"est={r.overlap_estimate:.2f} [{flag}]"
        )
    return 0


if __name__ == "__main__":
    raise SystemExit(main(sys.argv))
```

## Reading the number, and why it is a proxy, not a percentage

`overlap_estimate` here is inlier matches divided by the smaller of the two keypoint counts. That is not the same quantity as "percent of frame B's pixel area that also appears in frame A," which is what "The 70-80% Overlap Target in Practice: Counting Steps, Not Percentages" argues you should actually be aiming for and why counting steps is often the more honest way to hit it. Our ratio is a correlate of true geometric overlap, not a measurement of it: two frames that share a small but highly-textured region can score high on this proxy while genuinely overlapping only a modest fraction of their area, and two frames that overlap heavily across a low-texture wall can score low simply because ORB could not find enough repeatable keypoints there. Treat the number as a threshold trip-wire, not a percentage to report in a capture log.

That said, the field-tested overlap targets from photogrammetry practice give you a sane threshold to tune against. Pix4D recommends at least 75% frontal overlap generally, rising to around 90% specifically for interior reconstruction (Pix4D — Best practices for image acquisition and photogrammetry), while the older CIPA 3x3 Rules for architectural documentation set a lower floor of at least 60% between successive photographs, dropping to one-third for convergent, angled pairs (CIPA 3x3 Rules — photogrammetric documentation of architectural heritage). Given the gap between those numbers and the fact that this script measures a keypoint-ratio proxy rather than pixel-area overlap, do not chase a specific percentage from Pix4D or CIPA as if it maps 1:1 onto `overlap_estimate`. Instead, capture a small labeled set from your own gear and lighting, where you already know by eye which consecutive pairs are thin, and pick the threshold value that separates them, then keep that threshold fixed for a given camera and room type.

The notes available for this book do not include a documented, tuned threshold for this specific ORB-ratio-inlier construction; that number is intentionally left as a per-deployment calibration knob rather than a fixed constant, because no source in this shelf's research covers it directly.

## Practical use in the field loop

Run this after every four or five shots, not after every single one; ORB and RANSAC on full-resolution phone JPGs take real time, and checking every consecutive pair the moment it lands is wasted work if your walking pace is already steady. A lightweight version of the same idea, running live rather than in a batch script, is what "Live Coverage Tracking: Am I Done With This Room?" builds out into a running per-room signal; this script is the single-pair primitive that a live loop would call repeatedly. If a pair flags LOW, the fix is almost always to step back to where the last good frame was taken and shoot one more frame partway to the current position, closing the gap while you are still physically standing there, rather than discovering the hole after the whole building has been walked and reshooting means coming back.
