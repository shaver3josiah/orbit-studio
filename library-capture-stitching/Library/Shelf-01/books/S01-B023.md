# Estimating Capture Blur Risk with a Laplacian-Variance Score

A solo operator walking a building room by room has no second photographer checking the back of the camera. The only feedback loop is whatever the capture tool computes on-device, in the second or two before the operator moves to the next spot. Before you can flag a blurry frame or trigger a reshoot, you need a number that tracks "sharp versus blurry" cheaply enough to run on every frame. The standard, well-worn answer is the variance of the Laplacian.

This book covers the score itself: what it measures, how to compute it in Python with OpenCV, and how to read the number it produces. It deliberately stays narrow. This book is the piece in between: given a captured frame, how do you score it.

## What the Laplacian measures

The Laplacian is a second-derivative operator. Applied to an image, it responds strongly wherever intensity changes rapidly, which is to say, at edges. A sharp photograph is full of distinct edges: door frames, grout lines, the edge of a countertop, text on a light switch. A blurry photograph has smeared those edges into gradual transitions, so the Laplacian response is weak almost everywhere.

Variance is the trick that turns "the Laplacian responds strongly at edges" into a single number for the whole frame. A sharp image produces a Laplacian response that swings between strong positive and negative values at edges and sits near zero on flat regions, so the response has high variance. A blurry image produces a Laplacian response that stays close to zero everywhere, so the response has low variance. According to "PyImageSearch — Blur detection with OpenCV (variance of Laplacian)," the entire method is one line: convolve the grayscale image with the Laplacian kernel, then take the variance of that output.

## Computing it

```python
import cv2
import numpy as np


def laplacian_variance(image_path: str) -> float:
    image = cv2.imread(image_path)
    if image is None:
        raise FileNotFoundError(image_path)
    gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
    laplacian = cv2.Laplacian(gray, cv2.CV_64F)
    return float(laplacian.var())
```

Two details matter here, and both come straight from the source rather than being incidental style choices. First, the operator runs on a grayscale image, since blur is a structural property of intensity edges, not color. Second, the output type is `cv2.CV_64F`, a 64-bit float, rather than the 8-bit unsigned type the input image uses. The PyImageSearch writeup is explicit about why: Laplacian derivatives can be negative (an edge can transition from light to dark or dark to light), and an 8-bit unsigned output would clip those negative values to zero, silently destroying half the signal the variance calculation depends on.

A minimal field-check script wraps that function with a threshold and a verdict:

```python
import sys


def check_frame(image_path: str, threshold: float = 100.0) -> None:
    score = laplacian_variance(image_path)
    verdict = "BLURRY" if score < threshold else "sharp"
    print(f"{image_path}: variance={score:.1f} ({verdict})")


if __name__ == "__main__":
    for path in sys.argv[1:]:
        check_frame(path)
```

Run it against a folder of captured frames and it prints one line per image: a variance number and a verdict. That is the entire "quick field check" this book promises. No model, no training step, no dependency beyond OpenCV and NumPy.

## Reading the number

The threshold of 100.0 above is not a law of physics, it is a starting point borrowed directly from the PyImageSearch worked example, which reports blurry test images scoring in the 64-83 range and sharp ones scoring 200 to 1000-plus. The source is explicit and repeated on this point, quoting the caveat directly: the threshold is "quite subjective to the contents of the image(s)" and must be tuned per dataset rather than treated as universal.

That caveat is not a hedge to skim past, it is the operational reality for an Orbit Capture session. A wide shot of a mostly blank hallway wall will produce a lower raw variance than a close-up of a tiled bathroom floor, even if both are in perfect focus, simply because the wall has fewer edges to begin with. A threshold tuned on textured, detail-rich rooms will falsely flag plain rooms as blurry, and a threshold tuned on plain rooms will let real blur through in detailed ones. The notes available to this book do not cover a validated way to normalize the score against scene texture, so treat any single fixed threshold as a rough default to be checked against your own capture set, not a value to hardcode and forget.

Given that, the practical process for setting a working threshold on a given phone and lens combination is to capture a small labeled set: a handful of frames you know are sharp (locked exposure, steady hold, close focus) and a handful you know are blurry (deliberately shaken, or shot while stepping), score all of them with `laplacian_variance`, and look at where the two groups separate.

```python
def calibrate_threshold(sharp_paths: list[str], blurry_paths: list[str]) -> float:
    sharp_scores = [laplacian_variance(p) for p in sharp_paths]
    blurry_scores = [laplacian_variance(p) for p in blurry_paths]
    lowest_sharp = min(sharp_scores)
    highest_blurry = max(blurry_scores)
    if highest_blurry >= lowest_sharp:
        print("warning: sharp/blurry score ranges overlap, threshold is unreliable")
    return (lowest_sharp + highest_blurry) / 2
```

This is not a statistically rigorous classifier, it is a midpoint between two small labeled sets, and the warning branch matters more than the return value: if your sharp and blurry frames overlap in score, the raw Laplacian variance is not currently separating them for your capture conditions, and the answer is to fix lighting or exposure, not to keep tuning the number.

## Why this belongs before the pipeline, not inside it

It is tempting to treat blur scoring as an afterthought, something to run once photogrammetry has already produced a bad reconstruction, and then trace backward to find which frame was the culprit. That is expensive: a full COLMAP structure-from-motion pass plus a gsplat training run, discovering afterward that three frames in one room were too blurry to contribute usable features, and then having to physically return to the building to reshoot. A Laplacian-variance check computed at capture time, on the phone, in the moment the frame is taken, converts that failure mode from "discovered days later, requires a return trip" into "flagged in the room, fixed by taking one more shot before moving on."

That framing is exactly the point where this book hands off.
