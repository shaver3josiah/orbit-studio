# Twenty Stations, One Bridge: A Sparse-View Playbook for Outdoor Splats

Twenty leveled equirectangular stills of a bridge and its approach roads sit at the hard end of the sparse-view spectrum. The companion volume "What Makes a Photoset Reconstructable" covers why station count and baseline matter in general; this volume assumes you already have posed, per-view crops in hand — produced either by COLMAP with a cubemap/perspective split, or by a feed-forward pointmap network, as covered in "Splitting the Sphere: Perspective Rigs for Panorama SfM in Practice" — and picks up at the gsplat training loop itself. Everything below follows the flag and parameter names in gsplat's own `examples/simple_trainer.py` (nerfstudio-project/gsplat) so it drops into that trainer rather than inventing a parallel one.

Twenty widely-spaced outdoor stations trigger the two failure modes the 2025-2026 sparse-view literature keeps naming: floaters and view-overfitting. InstantSplat established DUSt3R-init plus fast optimization as the baseline sparse-view recipe, and the wave that followed it — FSGS, DNGaussian, CoR-GS, and the newer Pi-GS (Feb 2026) — converges on the same three-part fix: monocular-depth-prior losses scored by Pearson correlation rather than raw L2, pseudo-view interpolation, and cluster-aware dropout instead of plain opacity reset. None of that literature tests this exact scenario — 20 outdoor bridge panoramas — so what follows is the code-level extrapolation the research notes recommend, not a benchmarked recipe.

## Turn on what gsplat already has

Appearance drift and edge anti-aliasing are config, not new code. gsplat exposes per-image appearance embeddings and two exposure-correction post-processors out of the box:

```python
from dataclasses import dataclass

@dataclass
class BridgeSplatConfig:
    app_opt: bool = True
    app_embed_dim: int = 16
    app_opt_lr: float = 1e-3
    app_opt_reg: float = 1e-6
    post_processing: str = "ppisp"
    bilateral_grid_shape: tuple[int, int, int] = (16, 16, 8)
    antialiased: bool = False
    pose_opt: bool = True
```

`app_opt` with a 16-dimensional embedding gives each of the 20 stations its own learned appearance code, which is the fix for stations shot at different times of day. `post_processing="ppisp"` is the newer of gsplat's two exposure correctors; spirulae-splat's docs note PPISP gives less color shift than the classic affine bilateral grid, which is why it's the default here rather than `"bilateral_grid"`. Leave `antialiased` off by default — gsplat issue #840 documents the Mip-Splatting-style AA filter deleting thin high-frequency structures like bicycle spokes, and a bridge's cable stays and railings are exactly that class of geometry. A/B it on your own scene before trusting it.

## Masking sky and transients before the loss, not after

Sky and moving traffic both violate the same assumption — a static, opaque surface at every pixel — so both get folded into one ignore-mask per training image, generated once during preprocessing (skyseg U-2-Net/onnx for sky; a YOLO+SAM pass, following the stechdrive-3dgs-utils or realitystack "3DGaussianTools" pattern, for cars and pedestrians) and loaded alongside each crop:

```python
import torch
from PIL import Image
from torchvision.transforms.functional import to_tensor
from torchvision.transforms import GaussianBlur


def load_ignore_mask(sky_mask_path: str, transient_mask_path: str, dilate_frac: float = 0.15) -> torch.Tensor:
    sky = to_tensor(Image.open(sky_mask_path).convert("L")) > 0.5
    transient = to_tensor(Image.open(transient_mask_path).convert("L")) > 0.5
    kernel = max(3, int(transient.shape[-1] * dilate_frac) | 1)
    transient = GaussianBlur(kernel_size=kernel)(transient.float()) > 0.05
    return sky.squeeze(0), transient.squeeze(0)
```

The ~15% dilation matches the realitystack write-up, which found it necessary to catch loose hair, backpack shadows, and motion blur that a tight segmentation mask leaves uncovered at a pedestrian's edges — on a bridge roadway, the same margin covers windshield glare and a car's motion-blurred tail lights. Feed the resulting boolean tensor into gsplat's dataset `mask` field, or, if you're on spirulae-splat instead, its `--model.apply_loss_for_mask` flag does the same job as a CLI switch.

## Depth regularization: correlation, not distance

With only 20 stations, most surfaces are seen from one or two viewpoints, which is exactly the regime where 3DGS free-floats Gaussians to explain a single image without any multi-view constraint to correct it. The fix reported across DNGaussian, MS-GS, and Pi-GS is a monocular-depth prior (Depth Anything v2 is the model named in the notes) scored by Pearson correlation, because a monocular depth map is only ever correct up to an unknown scale and shift — an L2 loss would fight the reconstruction's own scale instead of just shaping it:

```python
def pearson_depth_loss(rendered_depth: torch.Tensor, mono_depth: torch.Tensor, valid: torch.Tensor) -> torch.Tensor:
    pred = rendered_depth[valid] - rendered_depth[valid].mean()
    ref = mono_depth[valid] - mono_depth[valid].mean()
    corr = (pred * ref).sum() / (pred.norm() * ref.norm() + 1e-8)
    return 1.0 - corr
```

Sky pixels have no real depth to correlate against, so `valid` should exclude them along with the transient mask — reuse the same ignore-mask from the step above rather than maintaining a third tensor.

## Pruning floaters without a plain opacity reset

DropAnSH-GS (CVPR 2026) names the reason plain opacity-reset under-cleans outdoor scenes: neighboring Gaussians compensate for whatever gets zeroed out, so the floater comes back. TIDI-GS's alternative — score each Gaussian by spatial isolation, low opacity, and low learned importance together, then prune the composite score rather than opacity alone — is indoor-scoped in its own evaluation, and the notes flag outdoor transfer as unconfirmed, but the scoring idea is simple enough to borrow and test on your own bridge scene:

```python
def floater_score(means: torch.Tensor, opacities: torch.Tensor, importance: torch.Tensor, k: int = 8) -> torch.Tensor:
    dists = torch.cdist(means, means).topk(k + 1, largest=False).values[:, 1:]
    isolation = dists.mean(dim=1)
    isolation = (isolation - isolation.min()) / (isolation.max() - isolation.min() + 1e-8)
    opacity_term = 1.0 - opacities.squeeze(-1)
    importance_term = 1.0 - (importance - importance.min()) / (importance.max() - importance.min() + 1e-8)
    return isolation * opacity_term * importance_term


def prune_floaters(splats: dict[str, torch.nn.Parameter], score: torch.Tensor, threshold: float = 0.6) -> torch.Tensor:
    keep = score < threshold
    for key in ("means", "scales", "quats", "opacities", "sh0", "shN"):
        splats[key] = torch.nn.Parameter(splats[key][keep])
    return keep
```

Run this every few hundred steps, not every step — pruning too aggressively early starves the optimizer of the Gaussians it needs to explain the far bank and horizon, which is exactly the large-depth-range background every sparse-view failure-mode source in the notes calls out as the hardest region to clean.

## Wiring it together

```python
import torch.nn.functional as F
from gsplat import rasterization


def train_step(splats, optimizers, batch, mono_depth_model, step: int) -> float:
    rgb, alpha, info = rasterization(
        means=splats["means"], quats=splats["quats"], scales=splats["scales"],
        opacities=splats["opacities"], colors=splats["sh0"],
        viewmats=batch["viewmat"], Ks=batch["K"],
        width=batch["width"], height=batch["height"],
    )
    ignore = batch["sky_mask"] | batch["transient_mask"]
    photometric = F.l1_loss(rgb[~ignore], batch["image"][~ignore])

    with torch.no_grad():
        mono_depth = mono_depth_model(batch["image"])
    depth = pearson_depth_loss(info["depth"], mono_depth, ~ignore)

    loss = photometric + 0.05 * depth
    loss.backward()
    for opt in optimizers.values():
        opt.step()
        opt.zero_grad()

    if step > 0 and step % 500 == 0:
        score = floater_score(splats["means"].detach(), splats["opacities"].detach(), info["importance"])
        prune_floaters(splats, score)
    return loss.item()


def _demo() -> None:
    n = 200
    means = torch.randn(n, 3)
    opacities = torch.rand(n, 1)
    importance = torch.rand(n)
    score = floater_score(means, opacities, importance)
    assert score.shape == (n,)
    assert (score >= 0).all() and (score <= 1).all()
    depth = torch.rand(64, 64)
    mono = depth * 2.3 + 0.4
    valid = torch.ones_like(depth, dtype=torch.bool)
    assert pearson_depth_loss(depth, mono, valid).item() < 1e-4


if __name__ == "__main__":
    _demo()
```

`_demo` is a sanity check, not a benchmark: it confirms the correlation loss collapses to zero under a pure scale-and-shift transform (the case Pearson correlation is supposed to be invariant to) and that the floater score stays in a sane range before you point either function at real gsplat state.

For the nadir hole each tripod leaves in every station, mask-and-accept beats generative inpainting here — it's simpler for 20 stills, and it sidesteps the licensing questions in "Generative Fill and Its License Minefield," since several of the panorama depth-inpainting backbones surveyed alongside this technique (PaGeR, SHARP-360) carry non-commercial research licenses rather than the MIT terms of gsplat and stechdrive-3dgs-utils. Reserve pole-cap patching for later, only if a filled floor actually matters for the fly-through. Once the loop above is stable, a manual pass in SuperSplat (MIT, browser-based) to lasso out any stray sky or water floaters is still the standard last step before shipping.
