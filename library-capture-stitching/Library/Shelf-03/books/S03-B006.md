# The Trainer Field in Mid-2026: Brush, LichtFeld Studio, and the Quiet Stall of Nerfstudio

Which trainer should turn your twenty bridge panoramas into a splat: the CUDA-free one that runs anywhere, or the CUDA-only one that ships features every few weeks? In July 2026 that question has a cleaner answer than it did a year ago, mostly because one project went quiet, one went fast, and one has quietly become the most interesting piece of software in the whole open pipeline.

Four open trainers make up this landscape, and it helps to see them side by side before picking one. Brush (ArthurBrussee/brush, Apache-2.0) last tagged a release, v0.3.0, on 2025-09-14, but its main branch was still receiving commits as recently as 2026-07-20. gsplat (Apache-2.0), the CUDA rasterizer underneath most of these trainers, hasn't tagged a release since v1.5.3 on 2025-07-04, yet its main branch has picked up real capability in the months since. LichtFeld Studio (MrNeRF/LichtFeld-Studio, GPL-3.0) is the opposite story: v0.5.3 shipped 2026-06-24 with 316 commits behind it. And nerfstudio (Apache-2.0), the project that popularized splatfacto, hasn't seen a commit since 2025-07-29 or a release since v1.1.5 in November 2024. Same category of software, four very different trajectories.

## The no-CUDA option: Brush

Brush's whole pitch is portability. It runs on NVIDIA, AMD, and Apple Silicon GPUs, and it can train directly inside a WebGPU-capable browser, using wgpu and Burn instead of a CUDA toolchain ("Brush — Cross-Platform Local Gaussian Splatting Trainer"). That matters for exactly the reader this shelf is written for: a solo operator on a Windows laptop whose GPU vendor is not guaranteed to be NVIDIA. If you don't know what's inside the machine you're handed, or you're helping someone whose laptop has an AMD card, Brush is the trainer that doesn't force a hardware upgrade just to get a splat.

Two caveats keep Brush from being a full turnkey answer, though. First, it still expects COLMAP-format or nerfstudio-format camera poses as input; it does not estimate its own poses, so pycolmap or an equivalent structure-from-motion step stays in the pipeline no matter which trainer you choose. Second, the project's own materials describe it as "currently a proof of concept," with no published VRAM minimums and no benchmark comparison against gsplat, LichtFeld, or Postshot. That framing is honest rather than damning. Brush is the right default for local, offline, hardware-agnostic training precisely because a Colab T4 fallback already exists in this pipeline for anyone whose laptop can't carry the load. It's the same reasoning laid out in "The 2026 Orbit Studio Upgrade: A Reference Pipeline from Twenty Panoramas to Fly-Through": pick the trainer that works regardless of what's under the hood, and keep the cloud GPU as the safety net, not the primary plan.

## The fast-moving option: LichtFeld Studio and its plugin surge

If you know you have an NVIDIA GPU with CUDA 12.8 or newer, the calculus shifts. LichtFeld Studio has become the most actively developed native trainer in this group by a wide margin. Its v0.5.0 release, on 2026-03-18, added a plugin system, an embedded Python runtime, and MCP integration. v0.5.1 followed with viewport splitting and USD import/export. v0.4.2 had already added undistort handling and alpha-as-mask support. Then v0.5.3, on 2026-06-24, folded in 316 commits worth of work: a Vulkan viewer, VRAM improvements, and an asset manager ("GitHub - MrNeRF/LichtFeld-Studio releases"). The project also picked up sustained funding, with Core11 GmbH extending sponsorship through the end of 2026 and total backing reaching €36,500 ("Core11 Extends Support for LichtFeld Studio Through 2026"). None of this comes free: training requires CUDA and an NVIDIA GPU specifically, so Brush's portability advantage disappears the moment you commit to this trainer.

What makes LichtFeld Studio worth a close look for this exact project, though, isn't the core trainer. It's a plugin called Moshpit360, released 2026-05-23. Moshpit360 takes stitched equirectangular 360 video, raw Insta360 .insv files, standard flat video, or a plain folder of still images, and runs the entire path from there to a trained splat with no manual configuration. It auto-detects camera model and lens parameters, checks capture density, and, notably, replaces COLMAP's incremental structure-from-motion with GLOMAP for faster alignment before handing off directly to LichtFeld training ("Moshpit360 Brings One-Click 360° Video to 3DGS Plugin to LichtFeld Studio"). The plugin's own description is direct about the goal: it works "without requiring the user to touch stitching software, COLMAP, or any training configuration." A second plugin, lichtfeld-360-plugin, and a separate COLMAP-integration plugin round out an ecosystem that treats 360 capture as a first-class input rather than an edge case to be reframed around. For a project built on Insta360 stills, that's the closest thing in the current open-source field to a template for what an ingestion step should look like, and it's worth studying even if you end up training in Brush.

One structural note carries through regardless of which trainer wins your GPU: as of mid-2026, no production-ready open trainer, not Brush, not LichtFeld Studio, not gsplat's rasterizer, does true equirectangular Gaussian rasterization. Panoramas still need to become perspective views before any of these tools can use them. That reprojection step, and the overlap and pole-handling choices it involves, is covered in full in "Twenty Stations, One Bridge: A Sparse-View Playbook for Outdoor Splats." Moshpit360's auto-configuration happens after that reframing, not instead of it.

## The engine underneath: gsplat's unreleased progress

gsplat is the CUDA rasterizer that both nerfstudio and much of the wider ecosystem build on, and its pip-installable releases have been frozen at v1.5.3 since July 2025. That stall is misleading if you only check the release tab. The main branch has kept moving: 3DGUT distorted-camera extensions and per-ray gradients landed in March 2026, LiDAR rasterization landed the same month, a bilateral-grid alternative called PPISP arrived in January, and a roughly 30 percent speedup for 3DGUT on an A100 landed in June. None of this is packaged into a tagged release yet, so using it means tracking main directly rather than pip installing a version number.

The relevant question for this project is whether any of that closes the equirectangular gap. It doesn't, not yet. The 3DGUT work extends gsplat toward fisheye and other wide-field-of-view distorted-pinhole cameras, which is a genuinely different problem from full spherical rasterization. True panoramic Gaussian rasterization remains confined to research papers such as SPaGS, Spherical-GOF, and UniTriSplat, none of which are production trainers. So gsplat's progress is worth watching if this pipeline ever wants to skip the perspective-crop step for wide-angle, non-360 captures, but it changes nothing about the reframing requirement for full equirectangular stills today.

## The one to leave behind: nerfstudio

nerfstudio deserves a direct verdict because it used to be the default answer to "which trainer should I use," and it no longer is. Its last commit landed 2025-07-29, its last tagged release, v1.1.5, dates to November 2024, and splatfacto, its Gaussian splatting method, still can't render fisheye or equirectangular images because its gsplat-based rasterizer assumes a pinhole camera model throughout. There's nothing hostile in that assessment; the project simply stopped moving while Brush and LichtFeld Studio kept shipping. For new work in 2026, there is no capability nerfstudio offers that one of the two active projects doesn't already do as well or better, and picking it now means building on a foundation nobody is maintaining.

Two more names round out the field without changing the picture. OpenSplat (pierotofy/OpenSplat) keeps receiving commits, as recently as 2026-05-31, but hasn't been tagged since v1.1.4 in August 2024, and it carries AGPL-3.0, the strictest license among the open trainers here, worth flagging if downstream licensing terms matter to how this pipeline gets shared. On the closed-source side, Jawset Postshot (v1.1, released 2026-05-13) and Epic's RealityScan are useful as quality benchmarks. RealityScan added Gaussian splat export at v1.5 and handheld SLAM support at v2.1, but its actual splat training still runs downstream in Postshot, and neither product has a confirmed native equirectangular import mode. They're worth knowing about, not worth building on.

## What this means for a bridge shoot on a laptop

For the concrete case this shelf serves, twenty leveled equirectangular stills reframed into a handful of perspective views per station, the practical path is straightforward. Default to Brush for local, offline training, because it runs on whatever GPU the laptop happens to have, including no discrete GPU at all if the browser training path is used, and keeps the free Colab T4 as the fallback for a machine that can't carry the load locally. If the machine confirmed to have an NVIDIA GPU with a recent CUDA install, LichtFeld Studio is worth the switch, both for its faster development pace and because its Moshpit360 plugin is doing, natively, the exact ingestion job this pipeline builds by hand: auto-detecting the camera, swapping in GLOMAP for speed, and skipping manual configuration entirely. Either way, gsplat's unreleased main-branch work is worth watching but not yet acting on, and nerfstudio is worth skipping for anything new. Whichever trainer receives the images, they arrive the same way: reframed from equirectangular stills into perspective views first, then handed off, then eventually packaged into a shareable world, the subject of "Shipping a World: SOG, SPZ 4, and the New Web Splat Stack." The trainer changes. The two steps on either side of it don't.
