# Filtering Frames with Insufficient Parallax Before Training

A room-by-room Orbit Capture walk produces long runs of nearly identical frames: the operator pauses at a doorway, takes three shots to be safe, and moves on. Each of those three shots overlaps its neighbors almost perfectly in content but carries almost no parallax between them. Feed that straight into COLMAP and you are not helping the reconstruction, you are adding frames that either fail to register cleanly or register against a near-degenerate baseline that pollutes the sparse model with noisy triangulations. This book scripts a pre-training filter that looks at each frame against its immediate neighbors, estimates how much real parallax exists between them, and drops or flags the ones that fall below a usable threshold before the bundle ever reaches `feature_extractor`.

The problem this solves is described precisely in the geometry literature: when two camera positions differ only by rotation, with no translation, all corresponding rays intersect along the same line through the camera center, so there is no baseline to triangulate against and absolute structure cannot be recovered (Pure rotation as a degenerate two-view geometry configuration). Panorama stitchers actually rely on this same condition. Classic automatic stitching assumes the camera rotates about its optical center with no translation, which is exactly the case that defeats structure-from-motion, and real hand-held translation breaks the single-homography model stitchers depend on (Panorama stitching's single-viewpoint (no-parallax) assumption). Orbit Capture needs the opposite of a good panorama: it needs translation, and plenty of it, between frames that are meant to feed a 3D reconstruction rather than a flat mosaic. This volume is the practical complement to two siblings on the same failure mode: "Baseline Requirements for gsplat: Why Pure Rotation Fails Training" explains why the downstream trainer chokes on it, and "The Rotation-Only Trap: Diagnosing a Degenerate Baseline" covers how to recognize it after the fact in a sparse model that has already been built. This book is about catching it earlier, before a single COLMAP process spins up.

## What "parallax" means for a frame pair

We do not have per-frame depth or a full bundle adjustment at this stage, so the filter has to work off two images alone. The approach: detect features in each frame, match them against the next frame (and optionally a small window of following frames), estimate the relative rotation and translation from the matches, then measure how much of the observed pixel motion is left over once you cancel out the rotation. Pure rotation predicts zero residual motion after that cancellation. Real parallax leaves a measurable one.

Feature detection and matching here follow the same detect-match-verify shape COLMAP itself uses at reconstruction scale, just applied pairwise and cheaply. OpenCV's feature tutorials cover exactly this progression, from single-image descriptor extraction through matching to homography-based verification (OpenCV Feature Detection and Description tutorials), and recommend ORB as a free, unpatented alternative to SIFT for description (OpenCV Feature Detection and Description tutorials). Since this filter runs on every frame pair in a large capture, before any GPU-backed COLMAP process is even started, ORB's speed matters more than SIFT's slightly better discriminability. It is worth remembering that any gradient-based descriptor, ORB included, degrades under illumination change rather than failing at one hard threshold (Descriptor matching sensitivity to illumination change), so a pair that reads as low-parallax might really be a pair that is hard to match because the exposure drifted, not because the camera held still. The filter reports both counts so an operator can tell the difference.

## The filter

```python
from __future__ import annotations

import json
from dataclasses import dataclass
from pathlib import Path

import cv2
import numpy as np


@dataclass
class ParallaxResult:
    frame_a: str
    frame_b: str
    num_matches: int
    num_inliers: int
    median_parallax_px: float
    status: str  # "ok", "low_parallax", "insufficient_matches"


def load_gray(path: Path, max_dim: int = 1600) -> np.ndarray:
    img = cv2.imread(str(path), cv2.IMREAD_GRAYSCALE)
    if img is None:
        raise ValueError(f"could not read image: {path}")
    h, w = img.shape
    scale = max_dim / max(h, w)
    if scale < 1.0:
        img = cv2.resize(img, (int(w * scale), int(h * scale)))
    return img


def orb_matches(img_a: np.ndarray, img_b: np.ndarray, n_features: int = 4000):
    orb = cv2.ORB_create(nfeatures=n_features)
    kp_a, des_a = orb.detectAndCompute(img_a, None)
    kp_b, des_b = orb.detectAndCompute(img_b, None)
    if des_a is None or des_b is None:
        return [], [], []
    bf = cv2.BFMatcher(cv2.NORM_HAMMING, crossCheck=False)
    raw = bf.knnMatch(des_a, des_b, k=2)
    good = [m for m, n in raw if m.distance < 0.75 * n.distance]
    pts_a = np.float32([kp_a[m.queryIdx].pt for m in good])
    pts_b = np.float32([kp_b[m.trainIdx].pt for m in good])
    return good, pts_a, pts_b


def rotation_compensated_parallax(pts_a, pts_b, camera_matrix) -> tuple[float, int]:
    if len(pts_a) < 20:
        return 0.0, 0
    E, mask = cv2.findEssentialMat(
        pts_a, pts_b, camera_matrix, method=cv2.RANSAC, prob=0.999, threshold=1.0
    )
    if E is None or mask is None:
        return 0.0, 0
    inlier_mask = mask.ravel().astype(bool)
    if inlier_mask.sum() < 15:
        return 0.0, int(inlier_mask.sum())
    _, R, _t, pose_mask = cv2.recoverPose(
        E, pts_a[inlier_mask], pts_b[inlier_mask], camera_matrix
    )
    inv_k = np.linalg.inv(camera_matrix)
    a_h = np.hstack([pts_a[inlier_mask], np.ones((inlier_mask.sum(), 1))])
    a_rays = (inv_k @ a_h.T).T
    a_rotated = (R @ a_rays.T).T
    a_rotated_px = (camera_matrix @ (a_rotated / a_rotated[:, 2:3]).T).T[:, :2]
    residual = np.linalg.norm(pts_b[inlier_mask] - a_rotated_px, axis=1)
    return float(np.median(residual)), int(inlier_mask.sum())


def evaluate_pair(
    path_a: Path, path_b: Path, camera_matrix, min_inliers: int = 40, min_parallax_px: float = 4.0
) -> ParallaxResult:
    img_a, img_b = load_gray(path_a), load_gray(path_b)
    matches, pts_a, pts_b = orb_matches(img_a, img_b)
    if len(matches) < min_inliers:
        return ParallaxResult(path_a.name, path_b.name, len(matches), 0, 0.0, "insufficient_matches")
    parallax_px, inliers = rotation_compensated_parallax(pts_a, pts_b, camera_matrix)
    status = "ok" if parallax_px >= min_parallax_px and inliers >= min_inliers else "low_parallax"
    return ParallaxResult(path_a.name, path_b.name, len(matches), inliers, parallax_px, status)
```

`rotation_compensated_parallax` is the core idea: recover the relative rotation `R` between the pair from the essential matrix, then rotate frame A's bearing vectors by `R` and re-project them into frame B's pixel frame. If the true motion were pure rotation, those re-projected points would land exactly on the matched points in B, because rotation alone fully explains the observed correspondence. Any residual displacement after that cancellation is the part translation is responsible for, and that residual, in pixels, is the parallax signal this filter thresholds on. This is the same geometric fact the degenerate-baseline literature describes from the other direction: pure rotation collapses all rays onto the same line, meaning zero recoverable structure (Pure rotation as a degenerate two-view geometry configuration). A near-zero median residual here is the pre-training symptom of exactly that condition.

The intrinsics matrix passed in as `camera_matrix` should come from wherever the capture pipeline already tracks lens parameters. If frames were shot with locked exposure and a single lens (the phone-still workflow), a rough intrinsics estimate (focal length from EXIF, principal point at image center) is good enough for this filtering pass, since the goal is a threshold decision, not a final calibration. COLMAP's own `feature_extractor` defaults to the `SIMPLE_RADIAL` camera model and treats intrinsics as something to refine later during bundle adjustment (Command-line Interface -- COLMAP), so nothing this filter does needs to be more precise than that.

## Running it over a capture bundle

Captures on disk are typically a flat folder of numbered JPGs or a zip bundle exported from the capture tool. Reading a zip bundle's manifest and members is a two-line affair with the standard library: `ZipFile.namelist()` lists entries and `ZipFile.read(name)` returns raw bytes for each one, usable as a context manager (`zipfile` -- Python 3 official documentation). The driver below assumes neighbor order matches capture order, which mirrors how COLMAP's own `sequential_matcher` is meant to be used for video-like or ordered walkthrough sequences rather than unordered internet photo collections (Feature Extraction and Matching -- COLMAP).

```python
def scan_bundle(image_dir: Path, camera_matrix, window: int = 2) -> list[ParallaxResult]:
    frames = sorted(image_dir.glob("*.jpg"))
    results: list[ParallaxResult] = []
    for i, frame_a in enumerate(frames):
        for j in range(i + 1, min(i + 1 + window, len(frames))):
            results.append(evaluate_pair(frame_a, frames[j], camera_matrix))
    return results


def flag_low_parallax_frames(results: list[ParallaxResult]) -> set[str]:
    ok_partner: dict[str, int] = {}
    for r in results:
        if r.status == "ok":
            ok_partner[r.frame_a] = ok_partner.get(r.frame_a, 0) + 1
            ok_partner[r.frame_b] = ok_partner.get(r.frame_b, 0) + 1
    all_frames = {r.frame_a for r in results} | {r.frame_b for r in results}
    return {f for f in all_frames if ok_partner.get(f, 0) == 0}


def write_report(results: list[ParallaxResult], out_path: Path) -> None:
    payload = [r.__dict__ for r in results]
    out_path.write_text(json.dumps(payload, indent=2))
```

`scan_bundle` checks each frame against a small window of following frames rather than only its immediate successor, because a single low-parallax neighbor pair (the doorway-pause case) should not doom a frame if it still has good parallax against the frame two steps later. `flag_low_parallax_frames` only marks a frame as unusable if it fails to clear the threshold against every neighbor in its window, which is a deliberately conservative rule: better to keep a borderline frame that has at least one good relationship than to drop it and widen a gap in coverage. The report is written as JSON precisely so it can sit next to the bundle and feed the next stage of the pipeline, which is the same COLMAP run described in "Setting Up a gsplat Training Run from a COLMAP Sparse Model": either strip flagged frames from the `image_path` folder before calling `feature_extractor`, or keep them but exclude them from the initial pair search and let `image_registrator` attempt them later against an already-solid model (Command-line Interface -- COLMAP).

## Where the thresholds come from, and where they don't

`min_parallax_px = 4.0` and `min_inliers = 40` in the code above are starting points, not physical constants. Nothing in COLMAP's own documentation defines a canonical parallax threshold in pixels; the closest published guidance is qualitative, not numeric, such as COLMAP's FAQ noting that scenes with limited view overlap and little texture benefit from more distinctive features and guided matching rather than a specific residual cutoff (Frequently Asked Questions -- COLMAP). Treat the numbers here as a tunable starting point for a given lens and image resolution, and calibrate them against a known-good and a known-bad sequence from your own captures rather than trusting them as ground truth. That honesty matters more than a false sense of precision: this filter is meant to catch the obvious doorway-pause and static-tripod cases cheaply, not to replace the judgment a full bundle adjustment makes later.

The overlap guidance from photogrammetry practice is a useful sanity check when tuning the window size: roughly 66% overlap between consecutive frames, achieved by moving about a third of the field of view per shot, with every point on the subject ideally visible in at least three frames (Cultural Heritage Imaging -- Photogrammetry guidelines). A capture shot to that discipline will rarely trip this filter at all; a capture with long dwell-and-shoot pauses will trip it constantly, which is exactly the signal an operator needs before a multi-hour COLMAP run discovers the same thing the hard way.
