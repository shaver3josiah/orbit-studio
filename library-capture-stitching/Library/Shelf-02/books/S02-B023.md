# Scripting a Registration Health Report from COLMAP Output

A COLMAP run ends by printing a wall of numbers and quietly writing a sparse model to disk. Somewhere in that output is the one fact you actually need before you hand a scan off to gsplat training: did the reconstruction register the images you shot, or did it fracture into disconnected fragments that will produce a walkable scene for one hallway and nothing for the rest of the building. "Running Incremental Mapping and Reading the Reconstruction Stats" covers how to watch that process run; this book turns the artifacts it leaves behind into a single automated report you can run after every scan, unattended, from a script.

The report has one job: read the sparse model COLMAP wrote, compute a registration percentage, and print (or return) a health verdict. The percentage itself and its thresholds are the subject of "Reading a Registration Health Score: <60% Warning, ~95% Healthy" — this book assumes that score definition and focuses on the plumbing that produces the number from raw COLMAP output, reliably, in a form a tool can call.

## Two ways to get at the numbers

COLMAP gives you two independent paths to the same facts: the sparse model files on disk, and the mapper's own console log while it runs. A health-report script should prefer the model files, because they reflect the final, bundle-adjusted state of the reconstruction rather than a snapshot of what was true mid-run.

The official Output Format docs describe the layout: `images.txt` has two lines per registered image, the first with the image ID, quaternion, translation, camera ID, and name, the second listing every 2D keypoint as `(X, Y, POINT3D_ID)` with `-1` meaning the keypoint never got triangulated into a 3D point. `points3D.txt` has one line per triangulated point, including a reprojection-error field that's only meaningful after a global bundle adjustment has run. Counting entries in these files, cross-referenced against how many images you fed in, is the entire arithmetic behind a registration percentage.

The pycolmap bindings make this arithmetic a few lines instead of a text parser: `pycolmap.Reconstruction("path/to/sparse/model")` loads the model and exposes `.images`, `.points3D`, and `.cameras` as Python objects directly (per the pycolmap documentation). That's the version worth building a report around, with a plain-text fallback for environments where pycolmap isn't installed.

```python
from __future__ import annotations

import argparse
import json
import sys
from dataclasses import asdict, dataclass
from pathlib import Path


@dataclass
class RegistrationStats:
    total_images: int
    registered_images: int
    num_points3d: int
    mean_track_length: float
    mean_reprojection_error: float | None
    registered_fraction: float


def load_stats_pycolmap(sparse_dir: Path, total_images: int) -> RegistrationStats:
    import pycolmap

    reconstruction = pycolmap.Reconstruction(str(sparse_dir))
    registered = len(reconstruction.images)
    points = reconstruction.points3D

    if points:
        track_lengths = [len(p.track.elements) for p in points.values()]
        errors = [p.error for p in points.values() if p.error is not None]
        mean_track = sum(track_lengths) / len(track_lengths)
        mean_error = sum(errors) / len(errors) if errors else None
    else:
        mean_track = 0.0
        mean_error = None

    return RegistrationStats(
        total_images=total_images,
        registered_images=registered,
        num_points3d=len(points),
        mean_track_length=mean_track,
        mean_reprojection_error=mean_error,
        registered_fraction=registered / total_images if total_images else 0.0,
    )
```

`total_images` has to come from outside the reconstruction, since a model only knows about images it actually registered, never the ones it dropped. The natural source is the image directory you fed to COLMAP, or the row count of the `images` table in the COLMAP database before mapping ran. The script below takes the image directory as an explicit argument rather than guessing.

## A text-only fallback

Not every environment building this report will have pycolmap installed, particularly a lightweight CI job or a Raspberry Pi doing a quick sanity pass in the field. The plain-text `images.txt` and `points3D.txt` formats documented in COLMAP's Output Format page are simple enough to parse directly without depending on the binary `.bin` variants or a Python binding.

```python
def load_stats_text(sparse_dir: Path, total_images: int) -> RegistrationStats:
    images_txt = sparse_dir / "images.txt"
    points_txt = sparse_dir / "points3D.txt"

    registered = 0
    with images_txt.open() as f:
        for line in f:
            line = line.strip()
            if not line or line.startswith("#"):
                continue
            fields = line.split()
            if len(fields) >= 9 and fields[0].isdigit():
                registered += 1

    track_lengths: list[int] = []
    errors: list[float] = []
    with points_txt.open() as f:
        for line in f:
            line = line.strip()
            if not line or line.startswith("#"):
                continue
            fields = line.split()
            point_id, error = fields[0], float(fields[7])
            track_pairs = fields[8:]
            track_lengths.append(len(track_pairs) // 2)
            errors.append(error)

    mean_track = sum(track_lengths) / len(track_lengths) if track_lengths else 0.0
    mean_error = sum(errors) / len(errors) if errors else None

    return RegistrationStats(
        total_images=total_images,
        registered_images=registered,
        num_points3d=len(track_lengths),
        mean_track_length=mean_track,
        mean_reprojection_error=mean_error,
        registered_fraction=registered / total_images if total_images else 0.0,
    )
```

The `images.txt` parser only counts every other non-comment line, since `images.txt` alternates a pose line with a keypoints line for each image; checking `fields[0].isdigit()` and requiring at least the nine pose fields is enough to skip the keypoints line without needing a line-parity counter that breaks if a keypoints line happens to be empty.

## Wrapping it as a callable report

The health-score judgment itself belongs to its own book, but the report script needs somewhere to plug it in. Keep the threshold logic as a single small function so the report and any other caller (a CLI, a web dashboard, the field-facing tool from "Registration Diagnostics as a Feedback Loop to the Field Operator") agree on the same verdict from the same numbers.

```python
def classify(fraction: float) -> str:
    if fraction >= 0.95:
        return "healthy"
    if fraction >= 0.60:
        return "marginal"
    return "warning"


def build_report(sparse_dir: Path, image_dir: Path) -> dict:
    total_images = sum(
        1 for p in image_dir.rglob("*")
        if p.suffix.lower() in {".jpg", ".jpeg", ".png"}
    )

    try:
        stats = load_stats_pycolmap(sparse_dir, total_images)
    except ImportError:
        stats = load_stats_text(sparse_dir, total_images)

    report = asdict(stats)
    report["status"] = classify(stats.registered_fraction)
    return report


def main() -> int:
    parser = argparse.ArgumentParser(description="COLMAP registration health report")
    parser.add_argument("sparse_dir", type=Path)
    parser.add_argument("image_dir", type=Path)
    parser.add_argument("--json", action="store_true")
    args = parser.parse_args()

    report = build_report(args.sparse_dir, args.image_dir)

    if args.json:
        json.dump(report, sys.stdout, indent=2)
        print()
    else:
        pct = report["registered_fraction"] * 100
        print(f"Registered {report['registered_images']}/{report['total_images']} images ({pct:.1f}%)")
        print(f"Points3D: {report['num_points3d']}, mean track length: {report['mean_track_length']:.2f}")
        if report["mean_reprojection_error"] is not None:
            print(f"Mean reprojection error: {report['mean_reprojection_error']:.3f} px")
        print(f"Status: {report['status'].upper()}")

    return 0 if report["status"] != "warning" else 1


if __name__ == "__main__":
    raise SystemExit(main())
```

The exit code matters as much as the printed text. Returning 1 on a warning-tier scan means the report can gate a pipeline step (do not kick off gsplat training on a scan that fractured) purely through shell semantics, with no separate parsing of the script's own stdout required by the caller.

## Why registered image count, not point count, drives the score

It's tempting to score health off the number of triangulated points, since a bigger point cloud looks more impressive. The COLMAP tutorial is explicit that the real failure mode to watch for is fragmentation: "COLMAP will reconstruct multiple separate models if not all images end up registered into one connected model." A scan can produce a large, dense point cloud from one well-covered wing of a building while silently dropping every image from a second wing into an orphaned sub-model, or discarding them entirely. Registered-image fraction catches that; raw point count does not, because a small, tightly connected reconstruction can have plenty of points relative to its own registered images while still representing only half the walkthrough.

The mean reprojection error and mean track length are worth carrying in the report even though they don't drive the pass/fail verdict here, because they're the first two numbers worth checking when a scan reports "healthy" registration but the resulting Gaussian splat still looks wrong. Both are only meaningful once bundle adjustment has actually run, per the Output Format documentation, so a report generated mid-mapping run (rather than after the mapper writes its final model) should not be trusted for these two fields.

## Where this script lives in the pipeline

This report script sits right after `mapper` finishes and right before the model gets handed to `image_undistorter` and then gsplat training. Wire it in as a required, non-optional step, not an optional diagnostic someone remembers to run by hand: the entire value of an automated health report evaporates the moment it's something an operator has to think to invoke. A cron-style scan folder watcher, or a single line at the end of a capture-processing shell script, is enough — call `main()` with the scan's sparse-model directory and its source image directory, check the exit code, and only proceed to training on success.
