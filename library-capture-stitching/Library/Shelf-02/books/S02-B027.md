# Automating the Dual-Fisheye-to-Equirect Stitch Step in the Pipeline

The sibling volume "Stitching Dual-Fisheye to Equirectangular with Insta360 Tools" covers the stitch step as something a human does by hand: plug in the X4 Air, open Insta360 Studio, export a 2:1 JPG, drag it into the capture folder. That is fine for a one-off shoot. It stops being fine the moment a solo operator is running the Orbit Capture pipeline daily and the manual export becomes the one step that breaks the chain between "camera comes home" and "bundle goes to COLMAP." This book wraps that stitch step in code so it runs unattended as part of the automated pipeline, ahead of "Building the Bundle Ingestion Module: manifest.json to a COLMAP Project" and feeding straight into "Writing an End-to-End Bundle-to-Splat Orchestration Script."

## What the automation actually has to do

Three jobs, in order:

1. Find raw dual-fisheye captures that haven't been stitched yet.
2. Invoke the stitch step without a human clicking through a GUI.
3. Verify the output is a valid 2:1 equirectangular JPG before it's allowed anywhere near the bundle.

Step 2 is the honest gap in this book. The notes for this shelf confirm that the Insta360 SDK is split into a Camera SDK (connection, shooting control, file listing) and a Media SDK (preview, stitching, image/video export), and that in-camera stitching is not available for the raw dual-fisheye stream — stitching has to go through the Media SDK ("Insta360 Developer Resources — SDK Guide"). What the publicly available developer resources do not document is the Media SDK's exact function signatures or a batch-stitch CLI surface; that detail sits behind SDK registration. So the code below treats the stitcher as a black-box external command and isolates that one call behind a single function, `run_stitch()`, so that whichever concrete binding you end up with (a registered Media SDK build, or Insta360 Studio's command-line export if your version exposes one) slots into exactly one place without touching the rest of the pipeline.

## The watcher and the manifest contract

The automation's job is to turn "camera dumped some files onto disk" into "a validated equirect JPG sits in the capture folder with the metadata the ingestion module expects." That's a small state machine: unstitched raw pair found, stitch invoked, output validated, raw archived.

```python
from __future__ import annotations

import json
import shutil
import subprocess
import struct
from dataclasses import dataclass, field
from pathlib import Path

RAW_SUFFIXES = {".insv", ".insp"}
STITCH_TIMEOUT_S = 300


@dataclass
class StitchJob:
    raw_path: Path
    output_path: Path
    status: str = "pending"
    error: str = ""


def find_unstitched(capture_dir: Path) -> list[StitchJob]:
    jobs = []
    for raw in sorted(capture_dir.glob("*")):
        if raw.suffix.lower() not in RAW_SUFFIXES:
            continue
        expected = raw.with_suffix(".equirect.jpg")
        if not expected.exists():
            jobs.append(StitchJob(raw_path=raw, output_path=expected))
    return jobs


def run_stitch(job: StitchJob, stitch_binary: Path) -> None:
    # ponytail: the Media SDK's own call surface isn't publicly documented
    # (see this shelf's research gaps), so this shells out to whatever
    # concrete stitcher you've registered for -- Media SDK build or
    # Insta360 Studio CLI export -- rather than binding to an API we
    # can't verify. Swap the subprocess call, not the surrounding pipeline.
    cmd = [
        str(stitch_binary),
        "--input", str(job.raw_path),
        "--output", str(job.output_path),
        "--format", "equirect",
    ]
    result = subprocess.run(
        cmd,
        capture_output=True,
        timeout=STITCH_TIMEOUT_S,
        text=True,
    )
    if result.returncode != 0:
        job.status = "failed"
        job.error = result.stderr.strip() or "stitch binary returned nonzero"
        return
    job.status = "stitched"
```

`find_unstitched` treats the raw dual-fisheye file (`.insv` for video-mode 360 captures, `.insp` for single stills) and its equirect JPG as a pair keyed by filename, so re-running the watcher after a partial failure just picks up where it left off. `run_stitch` is deliberately thin: one subprocess call, one timeout, one place to swap in a real binding later.

## Verifying 2:1 before anything downstream sees it

A stitcher that silently emits a slightly-off aspect ratio is worse than one that crashes loudly, because the failure shows up two stages later as a warped scene instead of at the source. The equirectangular projection maps horizontal pixel position directly to longitude and vertical position directly to latitude with no further transform, which only covers the full 360x180 degree sphere when width is exactly twice height ("Equirectangular Projection — PanoTools.org Wiki"). That source's own example of a non-compliant file (1650x824, one pixel short of true 2:1) is exactly the kind of off-by-one a lossy export pipeline can introduce, and it's cheap to catch before ingestion rather than debug after a bad splat.

```python
def read_jpeg_dimensions(path: Path) -> tuple[int, int]:
    with path.open("rb") as f:
        data = f.read()
    if data[0:2] != b"\xff\xd8":
        raise ValueError(f"{path} is not a JPEG (bad SOI marker)")
    i = 2
    while i < len(data):
        if data[i] != 0xFF:
            i += 1
            continue
        marker = data[i + 1]
        if marker in (0xC0, 0xC2):
            height, width = struct.unpack(">HH", data[i + 5:i + 9])
            return width, height
        segment_len = struct.unpack(">H", data[i + 2:i + 4])[0]
        i += 2 + segment_len
    raise ValueError(f"{path} has no SOF marker; couldn't read dimensions")


def validate_equirect(path: Path, tolerance: float = 0.01) -> None:
    width, height = read_jpeg_dimensions(path)
    ratio = width / height
    if abs(ratio - 2.0) > tolerance:
        raise ValueError(
            f"{path.name} is {width}x{height} (ratio {ratio:.4f}), "
            f"not the required 2:1 equirectangular aspect"
        )
```

This walks the JPEG's own marker structure to pull width and height straight out of the SOF0/SOF2 segment rather than depending on an image library, which keeps the validator dependency-free and fast enough to run on every file without slowing the watcher loop down. A `1%` tolerance covers ordinary rounding in the encoder without letting through anything an equirect-aware viewer would choke on.

## Tagging the panorama and handing off

Photo-sphere viewers (and, more importantly for this pipeline, anything downstream that inspects the file for context) look for Adobe XMP metadata in Google's GPano namespace to confirm a JPG is really a full equirectangular panorama, with `FullPanoWidthPixels`/`FullPanoHeightPixels` describing the full sphere and `PoseHeadingDegrees` recording compass heading at image center ("Photo Sphere XMP Metadata (GPano) — Google for Developers"). Writing that metadata is a job for the same stitch call if your binding supports it, or a lightweight post-pass if not; either way, the automation records the values it knows into the job manifest so nothing downstream has to re-derive them:

```python
def build_manifest_entry(job: StitchJob, width: int, height: int) -> dict:
    return {
        "source_raw": job.raw_path.name,
        "equirect_file": job.output_path.name,
        "width": width,
        "height": height,
        "projection": "equirectangular",
        "status": job.status,
    }


def stitch_capture_folder(capture_dir: Path, stitch_binary: Path) -> list[dict]:
    entries = []
    jobs = find_unstitched(capture_dir)
    for job in jobs:
        run_stitch(job, stitch_binary)
        if job.status != "stitched":
            entries.append(build_manifest_entry(job, 0, 0))
            continue
        try:
            width, height = read_jpeg_dimensions(job.output_path)
            validate_equirect(job.output_path)
        except ValueError as exc:
            job.status = "invalid"
            job.error = str(exc)
            entries.append(build_manifest_entry(job, 0, 0))
            continue
        raw_archive = capture_dir / "_raw" / job.raw_path.name
        raw_archive.parent.mkdir(exist_ok=True)
        shutil.move(str(job.raw_path), raw_archive)
        entries.append(build_manifest_entry(job, width, height))
    manifest_path = capture_dir / "manifest.json"
    manifest_path.write_text(json.dumps(entries, indent=2))
    return entries
```

This is the seam that "Building the Bundle Ingestion Module: manifest.json to a COLMAP Project" picks up: by the time that module opens `manifest.json`, every entry with `status: "stitched"` already points at a validated 2:1 equirect JPG sitting next to it in the capture folder, with the raw dual-fisheye source moved out of the way into `_raw/` so it doesn't get mistaken for another image to ingest. No manual export, no manual drag-and-drop, no human in the loop between camera and bundle.

## What this doesn't solve yet

Two things stay out of scope here on purpose. First, this watcher runs stitches sequentially and synchronously; a solo operator processing one building's worth of rooms at a time won't notice, but it is a naive design with a known ceiling worth flagging rather than hiding. Second, error recovery here is "mark it invalid and move on" — it does not retry, and it does not attempt any partial re-stitch. Both are reasonable starting points for a one-operator tool and reasonable things to revisit once volume or unreliability actually shows up; "Writing an End-to-End Bundle-to-Splat Orchestration Script" is where retry and parallelism policy for the whole pipeline, not just this step, belongs.

```python
def demo():
    from tempfile import TemporaryDirectory

    with TemporaryDirectory() as tmp:
        capture_dir = Path(tmp)
        (capture_dir / "room01.insv").write_bytes(b"fake-raw")

        def fake_stitch_binary(job_raw, job_out):
            width, height = 4000, 2000
            soi = b"\xff\xd8"
            sof = b"\xff\xc0" + struct.pack(">HBHHB", 8, 8, height, width, 3)
            eoi = b"\xff\xd9"
            job_out.write_bytes(soi + sof + eoi)

        jobs = find_unstitched(capture_dir)
        assert len(jobs) == 1
        fake_stitch_binary(jobs[0].raw_path, jobs[0].output_path)
        jobs[0].status = "stitched"

        width, height = read_jpeg_dimensions(jobs[0].output_path)
        assert (width, height) == (4000, 2000)
        validate_equirect(jobs[0].output_path)
        print("demo passed:", build_manifest_entry(jobs[0], width, height))


if __name__ == "__main__":
    demo()
```

The self-check builds a minimal synthetic JPEG (just the SOI, SOF0, and EOI markers) so `read_jpeg_dimensions` and `validate_equirect` can be exercised without a real Insta360 export on hand, and it fails loudly if the marker-walking logic or the aspect-ratio check ever regresses.
