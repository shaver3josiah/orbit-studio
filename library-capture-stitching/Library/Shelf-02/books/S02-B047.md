# Tuning gsplat for Low-Texture and Low-Light Interiors

A hallway with beige walls and no windows is the worst-case input for gsplat. COLMAP hands you a sparse, noisy point cloud with big gaps over the blank drywall, and gsplat's default densification and pruning settings were tuned against benchmark scenes (MipNeRF360-style, well-lit, textured) that do not look like that hallway. If you feed defaults a sparse-cloud interior, you get one of two failures: the optimizer never grows enough Gaussians to cover the gaps (a thin, see-through model), or it grows too aggressively on the noisy points that do exist and blows the memory budget on floating clutter. This book is about the knobs that separate those failures from a usable scene, and it assumes you already understand what training is optimizing in the first place, covered in "From Point Cloud to Splat: What Training Actually Optimizes."

## Why low-texture interiors break the defaults

gsplat ships three densification strategies, documented in the Strategy API: `DefaultStrategy` (the original ADC split/clone/prune behavior from Kerbl et al.), an Absgrad variant that accumulates absolute-value view-space gradients instead of signed ones, and `MCMCStrategy`, which reframes densification as stochastic-gradient Langevin dynamics with a hard cap on Gaussian count (gsplat: An Open-Source Library for Gaussian Splatting). The signed-gradient behavior of the default strategy matters specifically in low-texture rooms: two Gaussians pulling in opposite directions across a blank wall can cancel each other's accumulated gradient, so the region never crosses the growth threshold and never gets densified. Absgrad avoids that cancellation by accumulating magnitude regardless of sign, which is the more forgiving choice when your point cloud is already sparse over textureless surfaces.

The `DefaultStrategy` documented thresholds are:

- `prune_opa=0.005` — opacity floor below which a Gaussian is deleted
- `grow_grad2d=0.0002` — image-plane gradient threshold that triggers split or clone
- `grow_scale3d=0.01` — below this size a Gaussian is duplicated, above it, split
- `grow_scale2d=0.05` — 2D-scale split threshold
- `prune_scale3d=0.1`, `prune_scale2d=0.15` — oversized-Gaussian pruning thresholds
- `refine_start_iter=500`, `refine_stop_iter=15000`, `refine_every=100`, `reset_every=3000`

`MCMCStrategy` defaults are simpler: `min_opacity=0.005`, `refine_start_iter=500`, `refine_stop_iter=25000`, `refine_every=100`, `cap_max=1_000_000`.

None of these numbers are wrong, they are just calibrated for a point cloud with plenty of well-distributed matches. A low-texture interior needs the growth side loosened and the pruning side tightened, in that order, or you spend your compute budget growing garbage.

## Reading the room before you touch a threshold

Before adjusting anything, look at what COLMAP actually gave you. The FAQ page is explicit that weak-texture scenes need different upstream handling in the first place: higher input resolution, a larger patch-window radius, and a lower `filter_min_ncc` during dense stereo, plus DSP-SIFT with affine feature-shape estimation and guided matching, and disabling `ignore_two_view_tracks` so two-view-only tracks still triangulate (Frequently Asked Questions — COLMAP). If the sparse cloud is thin because of upstream matching decisions, no amount of gsplat tuning fixes that; you fix it before training and cross-check the actual failure signature against "Common Failure Signatures: Texture-Poor Rooms in the Sparse Model." What gsplat tuning fixes is what to do with the sparse cloud you already have.

```python
"""
inspect_sparse_cloud.py
Quick census of a COLMAP sparse model before choosing gsplat strategy
parameters. Uses pycolmap per "pycolmap Python bindings" (COLMAP docs).
"""
import pycolmap
import numpy as np

def summarize(sparse_path: str) -> dict:
    reconstruction = pycolmap.Reconstruction(sparse_path)
    points = reconstruction.points3D
    errors = np.array([p.error for p in points.values()])
    track_lengths = np.array([len(p.track.elements) for p in points.values()])

    return {
        "num_images": len(reconstruction.images),
        "num_points": len(points),
        "mean_track_length": float(track_lengths.mean()),
        "median_reproj_error": float(np.median(errors)),
        "points_per_image": len(points) / max(len(reconstruction.images), 1),
    }

if __name__ == "__main__":
    stats = summarize("colmap/sparse/0")
    print(stats)
```

`points3D.txt`'s per-point fields (`POINT3D_ID, X, Y, Z, R, G, B, ERROR, TRACK[]`) are exactly what this script reads, and `ERROR` is the mean reprojection error that only gets updated after a global bundle adjustment runs (Output Format — COLMAP). A low `points_per_image` count and short mean track length are your signal that you are in sparse-cloud territory and should loosen growth thresholds; a low `mean_track_length` also predicts more triangulation noise, which argues for tighter pruning at the same time. That tension, grow more but prune the junk harder, is the whole tuning problem in one sentence.

## Loosening growth without inviting noise

The direct lever for "not enough densification over blank walls" is `grow_grad2d`. Lowering it makes more of the image-plane gradient signal count as evidence a region needs more Gaussians, which matters when your legitimate gradient signal is already weak because there is little texture to disagree about. Extending `refine_stop_iter` past the 15000-iteration default gives the optimizer more cycles to keep growing into gaps that a well-textured scene would have filled by then.

```python
"""
strategy_config.py
gsplat DefaultStrategy tuned for a sparse, low-texture interior capture.
Field names and defaults per gsplat docs, Strategy API
(docs.gsplat.studio/main/apis/strategy.html).
"""
from gsplat.strategy import DefaultStrategy

def sparse_interior_strategy() -> DefaultStrategy:
    return DefaultStrategy(
        prune_opa=0.003,
        grow_grad2d=0.00012,
        grow_scale3d=0.01,
        grow_scale2d=0.05,
        prune_scale3d=0.08,
        prune_scale2d=0.12,
        refine_start_iter=500,
        refine_stop_iter=20000,
        refine_every=100,
        reset_every=3000,
    )
```

Two changes do the real work here. Dropping `grow_grad2d` from 0.0002 to roughly 0.00012 lets marginal gradients over low-texture surfaces trigger growth that the default would ignore. Tightening `prune_scale3d` and `prune_scale2d` downward (0.1 to 0.08, 0.15 to 0.12) removes the oversized, blurry Gaussians that low-texture regions tend to produce when the optimizer, lacking a strong gradient signal, settles for one big flat splat instead of several small accurate ones. Lowering `prune_opa` slightly, from 0.005 to 0.003, gives new low-confidence Gaussians in dim regions a bit more runway before they get deleted, since low light means the network needs more iterations to build enough confidence in a Gaussian's opacity to keep it.

## When MCMC is the better fit

If the interior is not just low-texture but genuinely sparse in registered images too (a small solo-operator capture bundle rather than a dense multi-hundred-image dataset), `MCMCStrategy`'s behavior is often more stable than `DefaultStrategy`'s split/clone/prune cycle, because its stochastic relocation of low-opacity Gaussians toward high-error regions does not depend on a strong local gradient signal the way ADC-style growth does. The tradeoff is `cap_max`: with a genuinely sparse point cloud you want that cap high enough that the optimizer is not artificially throttled while it is still trying to cover walls, but not so high that a small low-quality capture wastes memory on noise.

```python
"""
mcmc_config.py
MCMCStrategy tuned for a sparse-capture, dim interior.
Defaults per gsplat docs, Strategy API.
"""
from gsplat.strategy import MCMCStrategy

def sparse_interior_mcmc() -> MCMCStrategy:
    return MCMCStrategy(
        min_opacity=0.003,
        refine_start_iter=500,
        refine_stop_iter=25000,
        refine_every=100,
        cap_max=600_000,
    )
```

`cap_max` is set below the library's documented 1,000,000 default here deliberately: a single-room, low-texture capture bundle from one solo operator walking with a phone rarely has enough distinct 3D structure to productively fill a million Gaussians, and letting the optimizer try anyway just spends training time relocating noise. Start lower and raise it only if you watch the loss curve still improving near the cap, which is exactly the kind of signal covered in "Monitoring gsplat Training Loss and Point Cloud Growth."

## Low light adds a second, separate problem

Everything above addresses sparse geometry. Low light adds a photometric problem on top of it: SIFT and other gradient-based descriptors are not fully illumination-invariant, and matching accuracy for classic descriptors degrades measurably, not cleanly at one threshold, as illumination divergence between images increases (Descriptor matching sensitivity to illumination change). That degradation happens upstream in COLMAP, before gsplat ever sees the data, but its downstream effect on gsplat tuning is real: a dim room's sparse cloud carries more matching noise per point than a bright room's sparse cloud of the same density, which is one more reason to keep pruning thresholds tighter than the library defaults rather than looser. If registration itself is failing outright in dim rooms rather than just producing a noisier cloud, that is a capture and matching problem, not a gsplat tuning problem, and belongs in the earlier pipeline stage, not here.

## A minimal decision rule

You do not need to grid-search every parameter. In practice, three observations from the point-cloud census script above are enough to pick a starting configuration: points per image, mean track length, and whether the capture bundle itself is small (tens of images) or large (hundreds).

```python
"""
choose_strategy.py
Cheap heuristic for picking a gsplat densification strategy and starting
thresholds from sparse-cloud statistics. Not a substitute for watching
the actual training loss once it runs.
"""
def choose_strategy(points_per_image: float, mean_track_length: float,
                     num_images: int) -> str:
    sparse_cloud = points_per_image < 400 or mean_track_length < 3.0
    small_bundle = num_images < 80

    if sparse_cloud and small_bundle:
        return "mcmc_capped_600k"
    if sparse_cloud:
        return "default_loosened_grad2d"
    return "default_stock"
```

The thresholds in this heuristic (400 points per image, a mean track length of 3, an 80-image bundle) are working rules of thumb built from the pattern in the sources above, not numbers COLMAP or gsplat publish as a hard boundary. Treat them as a starting point to override once you see the actual loss curve, not as ground truth.
