# Writing a Loop-Closure-Aware Matching Pass for Room Sequences

A room-by-room capture is a walk, not a jumble: you shoot the entry hall, then the kitchen, then the hallway, then the bedrooms, and you eventually come back past the entry hall on your way out. `sequential_matcher` is built for exactly that shape of data, matching each image against its near neighbors in capture order ("Feature Extraction and Matching," COLMAP official docs). That's the right default for a walkthrough, and it's fast. But it is also, by construction, blind to the one thing a walkthrough guarantees: you will pass through the same physical space twice, at two very different points in the image sequence, and sequential matching never puts those two frames in the same pair.

That's a loop closure, and skipping it isn't a minor accuracy loss. Per-step pose error compounds from sensor noise, motion-model error, and featureless regions as the reconstruction grows, and loop closure is specifically the constraint that lets a mapping system recognize "I've been here before" and correct that accumulated drift ("Loop closure detection role in SLAM," SLAMTEC). Classical visual SLAM systems handle this with a dedicated place-recognition index (FAB-MAP, VINS-Mono, and ORB-SLAM3 all use Bag-of-Words retrieval for it), which is the same idea COLMAP's `vocab_tree_matcher` implements for offline SfM: instead of matching by sequence position, it retrieves visually similar images from anywhere in the set. The companion volume "Loop Closure and Why COLMAP Needs to Recognize Return Visits" covers why this matters for a splat's global consistency; this book is the implementation: a second matching pass, run after the sequential pass, that specifically checks late-sequence frames against early ones.

## The two-pass shape

The pattern is simple and it's deliberately not a replacement for sequential matching, just an addition:

```python
import subprocess
from pathlib import Path


def run_colmap(args: list[str]) -> None:
    subprocess.run(["colmap", *args], check=True)


def sequential_pass(database_path: Path) -> None:
    run_colmap([
        "sequential_matcher",
        "--database_path", str(database_path),
        "--SiftMatching.use_gpu", "1",
    ])


def loop_closure_pass(database_path: Path, vocab_tree_path: Path) -> None:
    run_colmap([
        "vocab_tree_matcher",
        "--database_path", str(database_path),
        "--VocabTreeMatching.vocab_tree_path", str(vocab_tree_path),
        "--SiftMatching.use_gpu", "1",
    ])


def build_matches(database_path: Path, vocab_tree_path: Path) -> None:
    sequential_pass(database_path)
    loop_closure_pass(database_path, vocab_tree_path)
```

Both commands write into the same COLMAP database, so the loop-closure pass doesn't discard anything the sequential pass found; it adds retrieval-based pairs on top ("Command-line Interface," COLMAP official docs, lists `sequential_matcher` and `vocab_tree_matcher` as separate, independently invokable matching commands operating on the same database). Running `vocab_tree_matcher` over the whole image set means it isn't limited to comparing "late" frames against "early" frames specifically, it retrieves similar images regardless of position, which is actually the safer default: you don't have to guess where in the sequence the operator doubled back.

That said, a full vocab-tree pass over every image is doing more work than a room-sequence loop check strictly needs, since most of its retrieved pairs will just re-confirm neighbors the sequential pass already matched. If you know roughly how long the walkthrough is and want to bias the pass toward the actual loop, restricting the candidate set to first-N-percent versus last-N-percent frames cuts the retrieval work down to the pairs that matter:

```python
def split_early_late(image_names: list[str], fraction: float = 0.25) -> tuple[list[str], list[str]]:
    if not 0 < fraction <= 0.5:
        raise ValueError("fraction must be in (0, 0.5]")
    n = max(1, int(len(image_names) * fraction))
    return image_names[:n], image_names[-n:]
```

There's no COLMAP-documented threshold for what fraction of a sequence counts as "early enough" or "late enough" to be a loop-closure candidate; that split is a judgment call for your capture pattern, not a value COLMAP ships or recommends. Say so plainly rather than pretending 25% is a load-bearing constant: it's a starting point to tune against your own floor plans. Once you have the split, COLMAP's own listed matcher set gives you the two honest options for narrowing the search: run `vocab_tree_matcher` (retrieval-based, works across the whole set without needing an explicit pair list) or fall back to `exhaustive_matcher` if the early/late subsets are small enough that all-pairs matching is cheap, since `exhaustive_matcher` is documented as suitable up to a few hundred images ("Feature Extraction and Matching," COLMAP official docs). For a single room sequence, the early and late slices are usually well under that ceiling, so exhaustive matching on just those two slices is often the cheapest correct answer:

```python
def exhaustive_loop_check(database_path: Path) -> None:
    run_colmap([
        "exhaustive_matcher",
        "--database_path", str(database_path),
        "--SiftMatching.use_gpu", "1",
    ])
```

If you go this route, extract early/late frames into their own COLMAP database (a fresh `feature_extractor` pass pointed at just those images), run `exhaustive_matcher` on it, and treat any pairs it finds as loop-closure evidence, distinct from the main sequential reconstruction's database. This is a heavier setup than just running `vocab_tree_matcher` once on the full set, so it only earns its keep when the vocab-tree pass is measurably too slow. Start with the single full-set `vocab_tree_matcher` pass and only split databases if profiling says you need to.

## Confirming the closure actually landed

Running the extra matcher isn't proof a loop closure was found and used; COLMAP only tells you what got registered and how well it fits once the mapper (and, specifically, bundle adjustment) has run. Two places to check, both grounded in documented output:

First, the incremental mapper's console log. Per-image lines look like `Registering image #241 (230)` followed by a line reporting how many of the image's points were matched against the existing model ("COLMAP incremental mapper console log format," PR #2420 discussion). By default only high-level milestones print; turn on `GLOG_v=1` (or `pycolmap.logging.verbose_level = 1`) to get the detailed per-image ratio, and watch specifically for the frames on the far side of your loop, the point where a late-sequence image registers against a model built almost entirely from early-sequence images is the loop closure actually taking effect.

Second, the `points3D.txt` output. Its `ERROR` field is the mean reprojection error for that point's track, and it is "only updated after a global bundle adjustment runs" ("Output Format," COLMAP official docs). Bundle adjustment is the step that jointly refines 3D points and camera poses given the accumulated observations across a track ("Bundle adjustment," Wikipedia, summarizing Hartley & Zisserman), so a track that spans your loop, an early-room point that also shows up in a late-room image, only gets meaningfully corrected once BA has run over the full model, not immediately when the matcher finds the pair. If your pipeline stops mapping early or you're inspecting an intermediate model, don't read the error field as final.

## Where this pass can go wrong

A vocab-tree or exhaustive match across distant frames is exactly the kind of comparison perceptual aliasing exploits: visually similar but spatially distinct places can produce near-identical descriptors, and that's the core mechanism behind false-positive loop closures, worse in repetitive environments ("Perceptual aliasing and false loop closures in repetitive environments," ROVER / arXiv 2508.13488). A hallway with identical doors on both ends, or a kitchen and a laundry room with the same cabinet run, is a real risk once you deliberately widen the matcher's search beyond sequence-adjacent pairs. "Choosing COLMAP Matcher Settings for Indoor Room Sequences" covers how to tune the matcher parameters this pass depends on, and "Handling Repeating Geometry: Avoiding False Loop Closures in COLMAP" is the dedicated treatment of catching and rejecting the false positives this wider search can introduce; treat this book's two-pass pattern as the mechanism and those two as the tuning and the safety net around it.

## A runnable self-check

The subprocess calls need a real COLMAP binary to exercise, but the split logic that decides what "early" and "late" mean doesn't, so it gets a plain assertion check:

```python
def _demo() -> None:
    names = [f"img_{i:04d}.jpg" for i in range(100)]
    early, late = split_early_late(names, fraction=0.2)
    assert len(early) == 20 and len(late) == 20
    assert early[0] == "img_0000.jpg"
    assert late[-1] == "img_0099.jpg"
    assert set(early).isdisjoint(late)
    try:
        split_early_late(names, fraction=0.6)
    except ValueError:
        pass
    else:
        raise AssertionError("expected ValueError for out-of-range fraction")
    print("split_early_late self-check passed")


if __name__ == "__main__":
    _demo()
```

Skipped: automatic detection of where a loop actually occurs in the sequence, that still requires either a fixed early/late split or a full vocab-tree pass over everything. Add automatic detection when you have enough captures to see a consistent pattern worth encoding.
