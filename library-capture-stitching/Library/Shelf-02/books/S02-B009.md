# Setting Up a COLMAP + gsplat Environment in Python 3.11

Every later book on this shelf assumes you can already run `colmap` from a shell and `import pycolmap` and `import gsplat` from Python without drama. This book is the one where you build that assumption. Nothing here produces a splat scene; it produces a toolchain that will not fall over the first time a bundle of JPGs from an Orbit Capture walkthrough hits it.

The environment has two halves that do not always want to agree with each other: COLMAP (a C++ structure-from-motion binary with Python bindings) and gsplat (a CUDA-backed PyTorch library for Gaussian-splat training). Both need a working CUDA toolchain if you want GPU speed, and both are picky about which Python and PyTorch versions they were built against. Python 3.11 is the target here because it is the version this shelf standardizes on for the rest of the pipeline (feeding bundles into COLMAP, and later into a gsplat training run).

## Why an isolated environment

Pin everything to one conda (or venv) environment instead of installing globally. COLMAP's Python bindings (pycolmap) and gsplat both compile CUDA extensions against a specific PyTorch build, and a system-wide upgrade to either PyTorch or your NVIDIA driver is a common way to silently break a working install. The pattern below uses conda because it can also manage the CUDA toolkit version alongside Python, which pip alone cannot do.

```bash
conda create -n orbit-splat python=3.11 -y
conda activate orbit-splat
```

## Installing COLMAP and pycolmap

COLMAP ships both as a standalone CLI binary and as `pycolmap`, a Python package exposing the same C++ core: scene classes such as `Reconstruction`, `Image`, `Camera`, `Frame`, `Rig`, and `Point3D`, a `Database` class, and the `IncrementalMapper` / `IncrementalPipeline` and `BundleAdjuster` used internally ("pycolmap Python bindings — COLMAP docs / DeepWiki"). You want both: the CLI for the batch pipeline steps, and pycolmap for anything that needs to read or script against a sparse model programmatically, which is exactly what "Reading the Bundle: Opening manifest.json and crops/*.jpg in Python" and later books do.

```bash
pip install pycolmap
```

On most Linux and Windows setups with a recent NVIDIA driver, the `pycolmap` wheel bundles a working COLMAP build, so this single install also gets you the `colmap` CLI on your PATH (check with `colmap --help` after activating the environment; if it is not found, install the COLMAP binary separately via your platform's package manager or a source build, then keep `pycolmap` pointed at a compatible version).

## Installing gsplat

gsplat is the open-source Gaussian-splat training library this shelf uses instead of the original 3D Gaussian Splatting research codebase. It implements the same core method (a 3D Gaussian scene representation seeded from SfM points, with interleaved optimization and adaptive density control) but as a modular, documented, Apache-2.0 licensed library built around custom CUDA kernels and PyTorch bindings ("gsplat: An Open-Source Library for Gaussian Splatting"). Compared to the original implementation, gsplat reports roughly 4x lower memory use (5.6 GB vs 9.0 GB on MipNeRF360 at 30k iterations) and up to about 10% faster training at equivalent quality, with its MCMC densification strategy cutting memory further to around 1.98 GB using far fewer Gaussians (1.00M vs 3.24M) than the original ADC strategy.

Because gsplat compiles CUDA extensions, install it after PyTorch is present and matched to your CUDA version:

```bash
pip install torch --index-url https://download.pytorch.org/whl/cu121
pip install gsplat
```

Swap the `cu121` index for whatever CUDA version your driver actually supports. If `pip install gsplat` fails to build, it is almost always a PyTorch/CUDA/driver mismatch, not a gsplat bug; recheck those three versions before anything else.

## Sanity-checking the install

Do not wait until you have a real Orbit Capture bundle to find out something is broken. Three checks, in order of how much they tell you when they fail.

First, confirm the CLI and its GPU path both work:

```bash
colmap --help
```

If this prints the COLMAP command list, the binary is on PATH and functional. COLMAP's matching stages default to GPU acceleration (`SiftMatching.use_gpu` defaults to enabled) ("Feature Extraction and Matching — COLMAP (official docs)"), so a CPU-only build will still run this shelf's pipelines, just slower; that is worth knowing before your first real reconstruction rather than discovering it thirty minutes into a mapper run.

Second, confirm pycolmap imports and exposes the objects the rest of this shelf depends on:

```python
import pycolmap

print(pycolmap.__version__)
reconstruction = pycolmap.Reconstruction
print(reconstruction)
```

A reconstruction is loaded from an existing sparse model with `pycolmap.Reconstruction("path/to/sparse/model")`, after which `.images`, `.points3D`, and `.cameras` become accessible as Python objects ("pycolmap Python bindings — COLMAP docs / DeepWiki"). You do not have a sparse model yet at this stage of the shelf, so the check here is only that the class exists and imports cleanly, not that it can load real data.

Third, confirm gsplat's CUDA extensions actually loaded (not just the pure-Python wrapper):

```python
import torch
import gsplat

print(torch.cuda.is_available())
print(gsplat.__version__)
```

If `torch.cuda.is_available()` returns `False` on a machine you expect to have a GPU, stop here and fix the driver/CUDA/PyTorch chain before moving on; gsplat's training loop will run on CPU but at a small fraction of the speed the shelf's later training-run book assumes.

## An end-to-end smoke test

The cheapest way to prove the whole toolchain works together, without needing a real Orbit Capture bundle yet, is to run COLMAP's all-in-one command against a handful of throwaway images and confirm it produces a sparse model pycolmap can then open.

```python
import shutil
import subprocess
from pathlib import Path

workspace = Path("smoke_test_workspace")
image_path = workspace / "images"
image_path.mkdir(parents=True, exist_ok=True)

# Drop a handful of overlapping JPGs into image_path before running this.

subprocess.run(
    [
        "colmap", "automatic_reconstructor",
        "--workspace_path", str(workspace),
        "--image_path", str(image_path),
        "--quality", "low",
        "--data_type", "individual",
    ],
    check=True,
)

import pycolmap

sparse_model_path = workspace / "sparse" / "0"
reconstruction = pycolmap.Reconstruction(str(sparse_model_path))
print(f"registered images: {len(reconstruction.images)}")
print(f"points3D: {len(reconstruction.points3D)}")
```

`automatic_reconstructor` runs the full sparse-plus-dense pipeline in one command, and its `--quality` flag (`LOW`, `MEDIUM`, `HIGH`, `EXTREME`) and `--data_type` flag (`INDIVIDUAL`, `VIDEO`, `INTERNET`) exist specifically to tune settings for the capture scenario, so `low` and `individual` here are chosen for smoke-test speed, not final reconstruction quality ("Command-line Interface — COLMAP (official docs)"). If this script runs to completion and prints a nonzero registered-image count, the CLI, its GPU path, and pycolmap's ability to read COLMAP's own output are all confirmed working together. This exact plumbing, a folder of JPGs in, a sparse model pycolmap can open out, is what "A First Pass: Feeding a Bundle Straight Through COLMAP" builds on directly, and the sparse model this smoke test produces is structurally the same kind of input "Setting Up a gsplat Training Run from a COLMAP Sparse Model" expects to seed Gaussian initialization from.
