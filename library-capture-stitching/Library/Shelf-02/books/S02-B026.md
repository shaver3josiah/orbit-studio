# Building the Bundle Ingestion Module: manifest.json to a COLMAP Project

A validated bundle is just a folder (or a zip, per "Reading the Bundle: Opening manifest.json and crops/*.jpg in Python") holding a `manifest.json` and a `crops/` directory of JPGs. COLMAP does not know what a "bundle" is. It wants a workspace directory containing an `images/` folder, and it wants `--workspace_path` and `--image_path` pointed at things that exist before you invoke `automatic_reconstructor` or the lower-level `feature_extractor` / `mapper` chain (Command-line Interface, COLMAP docs). The ingestion module's whole job is closing that gap: take the bundle's manifest and crops, and lay down a directory COLMAP can consume without complaint.

This book covers exactly that translation step. It does not choose feature extractors, matchers, or mapper types for different rig configurations; that decision lives in the sibling volume "Parameterizing COLMAP Runs Per Rig Type from manifest.json". It also does not re-validate that crops are readable JPGs or that the manifest parses; that's the earlier bundle-reading stage's job. Here, we assume a manifest and a crops directory that have already passed those checks, and we build the COLMAP project directory on top of them.

## What COLMAP actually expects on disk

The tutorial docs describe the pipeline as three stages -- feature extraction, matching plus geometric verification, then incremental reconstruction (Tutorial, COLMAP docs) -- and every one of those stages is invoked against a workspace path. The only hard requirement before you run anything is that `--image_path` resolves to a directory of images, and `--workspace_path` resolves to a directory COLMAP is allowed to write a `database.db` and a `sparse/` output into. Everything else (rig configs, camera model overrides) is layered on afterward.

That means the ingestion module's minimum viable output is small:

```
<workspace>/
  images/
    room01_0001.jpg
    room01_0002.jpg
    ...
  manifest.json        (copied in for provenance, not read by COLMAP)
```

The `sparse/` directory, and the `cameras.bin` / `images.bin` / `points3D.bin` (or `.txt`) files inside it, don't exist yet -- COLMAP writes those (Output Format, COLMAP docs). Our job stops at handing COLMAP a clean `images/` folder.

## The module

```python
from __future__ import annotations

import json
import shutil
from dataclasses import dataclass
from pathlib import Path


class BundleIngestionError(Exception):
    pass


@dataclass(frozen=True)
class CropEntry:
    filename: str
    room: str
    rig_type: str


@dataclass(frozen=True)
class BundleManifest:
    bundle_id: str
    rig_type: str
    crops: list[CropEntry]

    @classmethod
    def from_dict(cls, data: dict) -> "BundleManifest":
        try:
            crops = [
                CropEntry(
                    filename=c["filename"],
                    room=c.get("room", "unassigned"),
                    rig_type=c.get("rig_type", data["rig_type"]),
                )
                for c in data["crops"]
            ]
            return cls(
                bundle_id=data["bundle_id"],
                rig_type=data["rig_type"],
                crops=crops,
            )
        except KeyError as exc:
            raise BundleIngestionError(f"manifest missing required key: {exc}") from exc


def load_manifest(bundle_dir: Path) -> BundleManifest:
    manifest_path = bundle_dir / "manifest.json"
    if not manifest_path.is_file():
        raise BundleIngestionError(f"no manifest.json at {manifest_path}")
    return BundleManifest.from_dict(json.loads(manifest_path.read_text()))


def build_colmap_project(bundle_dir: Path, workspace_path: Path) -> Path:
    manifest = load_manifest(bundle_dir)
    crops_dir = bundle_dir / "crops"

    images_dir = workspace_path / "images"
    images_dir.mkdir(parents=True, exist_ok=True)

    missing = []
    for entry in manifest.crops:
        src = crops_dir / entry.filename
        if not src.is_file():
            missing.append(entry.filename)
            continue
        dst = images_dir / entry.filename
        if not dst.exists():
            shutil.copy2(src, dst)

    if missing:
        raise BundleIngestionError(
            f"manifest lists {len(missing)} crop(s) not present in {crops_dir}: "
            f"{missing[:5]}{'...' if len(missing) > 5 else ''}"
        )

    shutil.copy2(bundle_dir / "manifest.json", workspace_path / "manifest.json")
    return workspace_path
```

`load_manifest` and `BundleManifest.from_dict` intentionally do almost nothing beyond pulling out the fields this module needs: `bundle_id`, `rig_type`, and the crop list with each entry's `filename`, `room`, and (per-crop, falling back to the bundle-level) `rig_type`. Deeper manifest validation -- confirming every field's type, confirming the equirectangular crops are actually 2:1 -- belongs to the earlier stages covered in "Reading the Bundle" and "Validating an Equirectangular Export: 2:1 Ratio and Width > 3840px". By the time a bundle reaches this module, that work is already done; re-doing it here would just be duplicated logic drifting out of sync with the real validator.

`build_colmap_project` copies rather than moves or symlinks. `shutil.copy2` preserves the crop's mtime, which is harmless, and copying (instead of symlinking) means the bundle directory stays untouched and reusable if you need to re-run ingestion with different rig parameters later. If you're ingesting a bundle with a few thousand crops on a slow disk, this is the first place to optimize -- but that's a real measured bottleneck to chase down later, not a speculative one to design around now.

The explicit `missing` check matters more than it looks. A manifest that references a crop file that got deleted, renamed, or never wrote successfully is not a rare edge case -- it's the single most likely way a capture bundle goes bad in the field. Silently skipping a missing crop would hand COLMAP a workspace with fewer images than the manifest promises, and COLMAP would just reconstruct whatever it got without complaint (COLMAP will build multiple disconnected models, or a smaller model, if images don't register -- see Tutorial, COLMAP docs, on registration). Failing loudly here, before COLMAP ever runs, is much cheaper than debugging a thin point cloud an hour later.

## Where rig type comes in, and where it doesn't

The manifest carries a `rig_type` field (phone-in-hand stills vs. Insta360 X4 Air equirectangular) because different rigs need different COLMAP camera-model and matcher choices downstream -- that's the sibling volume's job, using `--ImageReader.camera_model`, `--ImageReader.single_camera_per_folder`, and matcher selection (Command-line Interface, COLMAP docs). This module reads `rig_type` only far enough to attach it to each `CropEntry`, so the next stage doesn't have to re-parse the manifest to know which images came from which rig. It deliberately does not write a `rig_config.json` for `colmap rig_configurator` here (Rig Support, COLMAP docs describes that config format and its `cam_from_rig_rotation` / `cam_from_rig_translation` fields) -- that belongs to the parameterization stage, which knows what COLMAP run it's about to launch and can decide whether rig constraints even apply.

One honest gap: the notes available for this shelf don't document Insta360's Media SDK stitching API surface in enough detail to say whether a bundle's equirectangular crops ever need re-stitching or re-tagging at ingestion time versus purely at capture time -- so this module treats every crop in `manifest.json` as already-finished, already-stitched image data, and does no image-level processing of its own.

## Self-check

```python
def _demo() -> None:
    import tempfile

    with tempfile.TemporaryDirectory() as tmp:
        tmp = Path(tmp)
        bundle_dir = tmp / "bundle"
        crops_dir = bundle_dir / "crops"
        crops_dir.mkdir(parents=True)

        for name in ("living_0001.jpg", "living_0002.jpg"):
            (crops_dir / name).write_bytes(b"\xff\xd8\xff\xd9")

        manifest = {
            "bundle_id": "bundle-001",
            "rig_type": "phone_stills",
            "crops": [
                {"filename": "living_0001.jpg", "room": "living"},
                {"filename": "living_0002.jpg", "room": "living"},
            ],
        }
        (bundle_dir / "manifest.json").write_text(json.dumps(manifest))

        workspace = tmp / "workspace"
        build_colmap_project(bundle_dir, workspace)

        assert (workspace / "images" / "living_0001.jpg").is_file()
        assert (workspace / "images" / "living_0002.jpg").is_file()
        assert (workspace / "manifest.json").is_file()

        (bundle_dir / "manifest.json").write_text(
            json.dumps({**manifest, "crops": manifest["crops"] + [{"filename": "ghost.jpg"}]})
        )
        try:
            build_colmap_project(bundle_dir, tmp / "workspace2")
        except BundleIngestionError:
            pass
        else:
            raise AssertionError("expected BundleIngestionError for missing crop")

    print("ok")


if __name__ == "__main__":
    _demo()
```

The demo builds a two-crop bundle, ingests it, and checks the resulting `images/` folder has exactly the files the manifest named. Then it adds a manifest entry with no backing file and confirms ingestion refuses to proceed rather than quietly building a partial workspace. That's the one behavior this module exists to guarantee: what comes out in `<workspace>/images/` matches what the manifest said should be there, every time, or the build stops before COLMAP ever sees it.
