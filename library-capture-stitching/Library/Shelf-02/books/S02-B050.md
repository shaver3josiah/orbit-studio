# Hardening the Pipeline: Retrying, Logging, and Failing Loud

A capture pipeline that works on the demo building and goes silent on the fifteenth real job is not a working pipeline. The orchestration script described in "Writing an End-to-End Bundle-to-Splat Orchestration Script" runs COLMAP and gsplat as subprocesses and treats a zero exit code as success. That is fine until a stitch produces a black frame, a feature_extractor call hangs on a corrupt JPG, or a gsplat training run plateaus at iteration 200 and burns four hours of GPU time before anyone notices. This book adds three things around that same script: retries for the failures that are actually transient, structured logs that a human or a dashboard can parse without guessing, and failure conditions that stop the run and say exactly why instead of limping forward with bad output.

## What "transient" actually means here

Not every failure deserves a retry. A `feature_extractor` call that dies because a JPG is truncated will die identically on attempt two. A stitch that fails because the Insta360 file transfer was interrupted mid-copy might succeed on a retry once the file finishes writing. The distinction matters because blind retries on a deterministic failure just burn wall-clock time before failing anyway, and the loud-failure requirement below only works if retries have already ruled out "it just needed another try."

Treat as retryable: subprocess calls that can fail due to filesystem races (reading a file still being written), GPU allocation contention (another process holding VRAM), or COLMAP matcher steps that can time out under system load. Treat as non-retryable and immediately loud: a missing input directory, an image count of zero, a training loss that has stopped decreasing, or a COLMAP reconstruction that registers a suspiciously small fraction of images. Retrying those wastes time and hides the real problem.

## A retry decorator, not a retry library

The stdlib has everything needed here. `functools.wraps` plus a loop covers exponential backoff without pulling in `tenacity` or `backoff` for what is a dozen lines:

```python
import functools
import logging
import random
import time

logger = logging.getLogger("orbit.pipeline")


class RetryableStageError(Exception):
    """Raised by a stage to signal 'try again', not 'stop everything'."""


def with_retry(max_attempts=3, base_delay=2.0, max_delay=30.0):
    def decorator(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            last_exc = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return fn(*args, **kwargs)
                except RetryableStageError as exc:
                    last_exc = exc
                    if attempt == max_attempts:
                        break
                    delay = min(max_delay, base_delay * (2 ** (attempt - 1)))
                    delay += random.uniform(0, delay * 0.1)
                    logger.warning(
                        "stage_retry",
                        extra={
                            "stage": fn.__name__,
                            "attempt": attempt,
                            "max_attempts": max_attempts,
                            "delay_s": round(delay, 2),
                            "reason": str(exc),
                        },
                    )
                    time.sleep(delay)
            raise last_exc
        return wrapper
    return decorator
```

The jitter on the delay (`random.uniform(0, delay * 0.1)`) is the one detail worth keeping even in a lazy version of this: without it, a batch of scans queued at the same time all retry in lockstep and hit the GPU scheduler at the same instant. `# ponytail: jitter is +/-10%, widen if you ever run more than a handful of concurrent jobs.`

Only functions that raise `RetryableStageError` get retried. Anything else (a `FileNotFoundError`, an `AssertionError` from a sanity check) propagates immediately, which is the mechanism that keeps non-retryable failures loud instead of getting three silent attempts first.

## Structured logging instead of scraping stdout

The script this book extends currently pipes COLMAP's stdout to a log file and hopes. COLMAP's incremental mapper actually emits a parseable format worth relying on directly: per the COLMAP incremental mapper console log format (PR #2420), it logs lines like `Registering image #241 (230)` followed by `=> Image sees 3755 / 8696 points`, and by default only high-level milestones print unless verbose logging is enabled via `GLOG_v=1`, `--v=1`, or `pycolmap.logging.verbose_level = 1`. That per-image registered-vs-total-points ratio is exactly the signal a health check needs, so the wrapper should turn on verbose logging and parse it rather than treating COLMAP's output as opaque noise:

```python
import json
import re
import subprocess
import sys
from pathlib import Path

REGISTER_RE = re.compile(r"Registering image #(\d+) \((\d+)\)")
POINTS_RE = re.compile(r"=> Image sees (\d+) / (\d+) points")


def log_event(event, **fields):
    record = {"event": event, **fields}
    logger.info(json.dumps(record))


@with_retry(max_attempts=2)
def run_mapper(database_path, image_path, output_path, env=None):
    cmd = [
        "colmap", "mapper",
        "--database_path", str(database_path),
        "--image_path", str(image_path),
        "--output_path", str(output_path),
    ]
    run_env = {**(env or {}), "GLOG_v": "1"}
    proc = subprocess.Popen(
        cmd, stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
        text=True, env=run_env,
    )
    registered = 0
    last_ratio = None
    for line in proc.stdout:
        line = line.strip()
        if m := REGISTER_RE.search(line):
            registered += 1
        if m := POINTS_RE.search(line):
            seen, total = int(m.group(1)), int(m.group(2))
            last_ratio = seen / total if total else 0.0
            log_event("mapper_progress", registered=registered, point_ratio=round(last_ratio, 3))
    proc.wait()
    if proc.returncode != 0:
        raise RetryableStageError(f"colmap mapper exited {proc.returncode}")
    return registered, last_ratio
```

Every `log_event` call emits one JSON object per line. That is the whole design decision: a JSON-lines log is a Unix pipe away from `jq`, a pandas `read_json(lines=True)` call, or the ingestion script behind "Building a Continuous Registration Health Dashboard Across Scans." Free-text log scraping requires the dashboard to know the orchestrator's phrasing; JSON-lines only requires it to know the field names, which change far less often.

## Detecting a stalled training run

gsplat's training loop does not fail loudly when it stalls; it just keeps iterating with a flat loss curve, and the process looks alive to any health check that only watches for a crash. The notes on gsplat's Strategy API give concrete numbers to anchor a stall check against: the `DefaultStrategy` only starts densifying at `refine_start_iter=500` and stops at `refine_stop_iter=15000`, refining every `refine_every=100` iterations, per gsplat documentation's Strategy API reference. A training run that shows no meaningful loss improvement across several refinement windows past iteration 500 is not "still warming up," it is stuck, and the earlier it is caught the less GPU time is wasted:

```python
from collections import deque


class TrainingStallError(Exception):
    pass


class StallMonitor:
    def __init__(self, window=5, min_relative_improvement=0.01, refine_start_iter=500):
        self.window = window
        self.min_relative_improvement = min_relative_improvement
        self.refine_start_iter = refine_start_iter
        self._losses = deque(maxlen=window)

    def observe(self, iteration, loss):
        if iteration < self.refine_start_iter:
            return
        self._losses.append(loss)
        if len(self._losses) < self.window:
            return
        oldest, newest = self._losses[0], self._losses[-1]
        if oldest <= 0:
            return
        improvement = (oldest - newest) / oldest
        if improvement < self.min_relative_improvement:
            raise TrainingStallError(
                f"loss improved only {improvement:.1%} over last {self.window} "
                f"checkpoints (iter {iteration}); training appears stalled"
            )
```

`window=5` and a 1% floor are starting points, not physics; a real deployment tunes them against a handful of known-good runs and leaves the knobs exposed rather than baking in a constant. `# ponytail: stall thresholds are guesses, recalibrate once you have real loss curves from your own scenes.`

## Failing loud on a bad reconstruction

A registration ratio matters more than a return code. COLMAP's own tutorial notes that COLMAP will produce multiple separate models if not all images register into one connected model, and its documented remedies for a failed or partial registration are denser matching or manually specifying the initial image pair. The mechanism that makes those remedies reachable at all is a check that stops the pipeline the moment registration looks wrong, instead of quietly handing a fragmented model to gsplat:

```python
def assert_healthy_reconstruction(sparse_model_path, total_images, min_registered_fraction=0.85):
    import pycolmap
    reconstruction = pycolmap.Reconstruction(str(sparse_model_path))
    registered = len(reconstruction.images)
    fraction = registered / total_images if total_images else 0.0
    log_event("reconstruction_check", registered=registered, total=total_images, fraction=round(fraction, 3))
    if fraction < min_registered_fraction:
        raise SystemExit(
            f"FATAL: only {registered}/{total_images} images registered "
            f"({fraction:.0%}) — below {min_registered_fraction:.0%} threshold. "
            f"Aborting before splat training; see docs on denser matching or "
            f"manual initial pair selection."
        )
```

`SystemExit` is the loud failure here on purpose: it is a distinct signal from "an exception got caught somewhere downstream," it carries a message the operator actually reads in the terminal, and it is exactly the trigger point that "Automating a Reshoot Request from a Failed Registration" hooks into to kick off a reshoot request instead of a support ticket. The notes for this shelf were candid that a specific numeric threshold like 85% is a convention this pipeline is choosing, not a value COLMAP itself defines; observed registration percentages across real datasets vary widely (roughly 46% to 92-100% depending on scene and parameters), so treat 0.85 as a starting default to tune against your own building stock, not a constant handed down from the tool.

## Wiring it together

None of these pieces are new abstractions bolted onto the orchestration script; they replace the naive subprocess calls and bare exit-code checks with the same functions doing more honest work. `run_mapper` gets the `@with_retry` decorator for the filesystem-race and GPU-contention cases; `assert_healthy_reconstruction` runs immediately after and raises `SystemExit` rather than warning and continuing; `StallMonitor.observe` gets called once per logged training iteration inside the gsplat training loop, and its `TrainingStallError` is deliberately not wrapped in `with_retry`, because retrying a stalled training run from the same checkpoint just stalls again. The retry decorator is for stages where trying again is a real fix; the loud failures are for stages where trying again would only delay finding out something is wrong.

```python
def demo():
    calls = {"n": 0}

    @with_retry(max_attempts=3, base_delay=0.01)
    def flaky():
        calls["n"] += 1
        if calls["n"] < 3:
            raise RetryableStageError("simulated transient failure")
        return "ok"

    assert flaky() == "ok"
    assert calls["n"] == 3

    monitor = StallMonitor(window=3, min_relative_improvement=0.05, refine_start_iter=0)
    monitor.observe(0, 1.0)
    monitor.observe(1, 0.99)
    try:
        monitor.observe(2, 0.98)
        raise AssertionError("expected TrainingStallError")
    except TrainingStallError:
        pass

    print("demo checks passed")


if __name__ == "__main__":
    demo()
```
